# 开关判定细则

本文件只服务「物料能不能拦住 → 拦不住才加实验」。不评审代码，不写任何业务需求对照。

## 两种闸门

### 物料闸门

检索、服务端或配置下发的数据决定代码走不走。常见形态：

- 新 type / 新 cmd / 新元素类型
- 新 JSON 字段，缺省走旧值或空值
- 新节点整体不下发
- 新类只由新 type 的工厂创建，旧 type 仍创建旧类

判定：把新增字段/type 从下发数据里拿掉，这段新逻辑是否根本进不去。进不去就是物料可控，不加实验。

### 实验闸门

云控、AB、Exp。不负责「有没有这套新样式」，只负责：

- 新料已经下发，但实验关闭时仍走线上
- 公共路径被改了，不下新料也会执行，必须能回到线上

判定：实验关掉后，旧物料表现是否和改之前一致。不一致就加开关，或证明改动行为等价。

## 读 git diff 时看什么

目标不是看 diff 漂不漂亮，而是还原「这段新逻辑怎么被调到」。

对每个 hunk：

1. **这是入口还是叶子？** 工厂 / 出窗 / 事件订阅 / parse 是入口。新 View bind、新动画、新 XML 多半是叶子。
2. **调用链上一层是谁？** hunk 里看不出入口时，读调用方、`when (type)`、`optXxx`、事件 `receiveEvent`。
3. **守卫条件是物料还是实验？** `type == 新值`、`field.isNotEmpty()`、`optJSONObject("new_node") != null` 是物料。Exp / 云控 conf 是实验。
4. **旧料会不会走进这个 hunk？** 旧 type 的 `when` 被改了、所有卡片都会收到的事件、基类方法被旧子类调用，都是「会」。
5. **缺省值是不是线上？** `optInt(key, 旧默认)` 且旧逻辑不读新字段，通常等价。缺省把旧路径切到新行为，则物料拦不住。

只看 `+` 行不够。公共函数多一个参数、公共事件多一个订阅、parse 多一个字段，都要问旧调用点会不会受影响。

## 分类

### 物料可控 → 不加实验

- 新文件、新类、新 XML、新动画只被新 type / 新工厂分支创建
- 新字段缺省等于线上旧值，且只有新分支读取
- 公共 parse 多读了字段，旧逻辑从不使用
- 新接口在无对应物料时是空操作

### 物料拦不住 → 加实验

- 线上旧 type 的工厂/管家被改，新 type 来了会抢原路径
- 公共事件，旧对象也会收到
- 公共布局/显隐，旧内容也会按新字段被藏起来
- 公共时序，旧任务完成路径被跳过或补发
- 实验关闭时仍按新 type 创建新实现

开关打在这些分叉点。关实验必须回落线上 type、线上事件、线上显隐、线上时序。

### 公共路径但行为等价 → 不加实验

- 基类新增方法，旧子类不调用
- 公共 parse 增加字段，旧逻辑不读
- 无对应 View 时直接 return
- 兼容重载，旧调用点行为不变

说明为什么等价。不要因为「改了公共文件」强行加开关。

## 开关打在哪

打：

- 工厂：新 type 来了，实验关则创建线上旧类
- 公共展示/出窗：实验关则 factoryType / 分支打回线上
- 公共事件：旧对象也会收到的完成、展示、隐藏
- 公共布局：会改变旧内容显隐的阶段/条件
- 公共时序：会改变旧完成顺序的 skip / 补发

不打：

- 新子类内部的 bind / 动画 / XML
- 只有新 type 才会创建的 View
- 缺省为空、只有新分支读取的字段
- 已经在上游工厂被拦住的调用点

跟随仓库现有实验读取方式。新增开关默认关。

## 误区

1. **当 CR 来用。** 不评质量、不改业务、不补物料。
2. **只搜实验函数。** 必须读 git diff 和调用链，看物料守卫。
3. **新文件没有实验就报漏。** 只被新 type 创建时，物料已拦住。
4. **改了公共文件就整文件包实验。** 先看旧调用点会不会走进新行为。
5. **检索承诺不乱下新 type，工厂就不用实验。** 新 type 一旦下发就会走新分支；实验的意义是「料发了也能关」。
6. **身份字段当成实验。** 新 `type=N` 能区分谁走新时序，但不能在实验关闭时阻止公共路径被改坏。身份是物料，能不能改公共时序看实验。
7. **给 15 个新 type 开 15 条实验。** 一条总开关足够，物料继续控 type。
8. **默认开。** 等于改现场。修线上缺陷的独立开关若必须默认开，单独说明，不要和本功能闸门混用。
