# 物料优先、实验兜底

只做开关。不是代码评审，不绑定任何需求或卡片。

职责只有两件：

1. **Check**：每一处改动，不发新增物料/字段时，新逻辑是否走不到、调不到。
2. **加实验开关**：只有物料拦不住、旧料也会走进去时，才在分叉点加实验开关。关实验必须走线上。默认关。

读 diff 是为了判断「这段业务逻辑的入口是不是新字段/新 type 控制的」，不是为了挑 bug、命名或架构。

## 触发边界

### 适用

- 检查实验开关、物料开关、云控开关有没有打对。
- 「物料优先、实验兜底」「不是每一行都包开关」「不发这个物料整段逻辑走不到」。
- 「关实验必须走线上、不影响现场」。
- 用户给出提交、暂存区或工作区，要求按这个原则过一遍或补实验开关。

### 不适用

- 普通 CR、找 bug、改业务、补协议字段、补物料。
- 只解释某段代码做什么。
- Lite 差异化标记：用 `lite-diff-marker`。
- 实现风格约束：用 `karpathy-guidelines`。

### 需要确认

没给仓库、提交或 diff 时，先确认审查范围。不要把某张卡片、某个需求写进规则。

## 核心原则

1. **物料优先。** 新 type、新字段、新配置节点不下发时，新逻辑走不到，就算物料控制住。叶子实现不再包实验。
2. **实验兜底。** 改动挂在旧 type、公共工厂、公共事件、公共布局、公共时序上，旧料也会执行，才加实验。关实验 = 线上。
3. **不是每一行都要开关。** 入口已经被物料或上游工厂拦住，内部实现不加实验。
4. **只加实验，不改业务。** 不改协议、不改物料、不改分支语义。只在分叉点把「新逻辑」和「线上逻辑」切开。
5. **实验默认关。** 默认开等于改现场。

## 必须先弄清 git diff

不读全量 diff 就不能判断物料能不能拦住。禁止只搜 `NadExp` / `if (exp)` 下结论。

### 1. 圈定改动面

用户点名的提交、暂存区、未提交工作区都要看。暂存区以 `git diff --cached` 为准；空就说空，已经进提交就审查那次提交。

```bash
git status --short
git diff --cached
git diff
git log --oneline -20
```

用户给了提交时：

```bash
git show --stat <commit>
git show <commit>
# 多笔提交
git diff <base>..<head>
git diff --name-status <base>..<head>
```

未跟踪的新文件用 `git ls-files --others --exclude-standard` 补进范围。只看 hunk 不够时，读调用点、工厂、parse、事件订阅。

### 2. 按改动点拆，不按文件名扫

每个业务改动点都要能回答：

- 运行时入口是什么（工厂、parse、事件、bind、回调）。
- 这段逻辑依赖哪些下发数据（新 type、新字段、新节点）。
- 把这些新数据拿掉，代码还会不会被调用。
- 若还会：关实验时是否仍走线上。

新增文件、公共基类新方法、公共 parse、公共事件订阅都算改动点。不要因为「这是新文件所以一定安全」或「改了公共文件所以一定要包实验」跳过追踪。

### 3. 判定

| 不发新料/新字段 | 关实验 | 动作 |
| --- | --- | --- |
| 走不到 | — | 不加实验 |
| 走得到 | 已回落线上 | 已有实验，不再包叶子 |
| 走得到 | 仍走新逻辑 | **加实验开关** |
| 走得到 | 行为与改前完全一致 | 不加。说明为什么等价 |

物料闸门：下发数据决定走不走。实验闸门：数据已经来了，或公共路径被改了，用开关保证关实验等于线上。

详细分类和误区见 `references/gate-rules.md`。

## 怎么加实验开关

只打在分叉点：旧路径也会走到的工厂、出窗、事件、布局、时序。

不要打在已经进入新物料分支的 bind、动画、XML、新字段读取上。

跟随仓库现有实验读取方式（云控 conf、Exp 对象、AB SDK），不要另起一套。新增开关默认关。

只插入判断和回落，不改回落后的线上逻辑。

## 输出

先报 check，再改代码。改完列出加了哪些开关、打在哪个分叉点、为什么物料拦不住。

```markdown
## 范围
提交 / 暂存区 / 工作区：...

## Check
| 改动点 | 入口 | 依赖的新物料/字段 | 不发新料能否执行 | 结论 |
| --- | --- | --- | --- | --- |

## 要加实验的点
物料拦不住的公共路径，以及准备打在哪。

## 不加实验的点
入口已被新物料/字段拦住，或公共改动行为等价。

## 已改文件
（只在实际加开关后列出）
```
