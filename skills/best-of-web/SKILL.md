# Best Of Web

目标：当任务需要结合互联网上高质量内容时，主动进行联网搜索、筛选可信来源，并把最有价值的观点综合成可执行、可引用的回答。

这个技能不是普通搜索命令。它强调“精选”和“综合”：少列链接，多判断来源质量、证据强弱和内容取舍。

## 触发边界

### 适用

- 用户明确说“结合互联网上最优秀的内容”“找全网最好的资料”“找权威资料”“找最佳实践”“找高质量参考”。
- 用户调用 `/best-of-web`。
- 用户的问题涉及推荐、调研、方案对比、学习路线、产品/技术选型、行业实践、论文/官方文档综述，且明显需要外部高质量资料支撑。
- 当前信息可能近期变化，且回答质量依赖最新公开资料，例如新框架、新产品、新政策、新模型、新论文或当前市场信息。

### 不适用

- 普通事实问答，已有可靠上下文即可回答。
- 单文件、单方法、少量本地 `rg` 就能解决的代码问题。
- 用户明确要求不要联网搜索。
- 只需要本地代码库、内部文档、iCafe、KU、日志或其他私有资料的任务。
- 需要在本地代码库、文档、日志、配置之间横向检索，或需要派子 agent 节约主线程上下文的任务；这类使用 `delegated-search`，而不是本技能。

### 需要确认

如果主题太宽，无法判断“优秀内容”的评价标准，先问一个简短问题来限定范围，例如目标受众、技术栈、时间范围或输出形式。

## 工作流程

1. 明确研究目标：提炼主题、用户真正要做的决策，以及评价“优秀”的标准。
2. 联网搜索：优先找一手来源、官方文档、原始论文、标准规范、权威机构资料和高信号专家文章。
3. 筛选来源：避开 SEO 拼贴、二手复述、无日期内容、低可信营销文和互相复制的摘要。
4. 交叉验证：对关键事实、数据、建议和结论至少用多个可靠来源互相校验。
5. 综合输出：把高质量内容整理成结论、取舍、行动建议或结构化清单，而不是简单堆链接。
6. 标注来源：给出使用过的关键来源链接；有冲突、不确定或证据薄弱时明确说明。

## 输出要求

- 开头直接给综合结论，不要先展示搜索过程。
- 对时效性强的信息，写明来源发布时间、更新日期或检索时点。
- 推荐或排序类回答要说明选择标准。
- 不要大段摘抄网页内容；必要引用时只给短摘录，并以自己的话解释。
- 如果当前环境没有联网搜索或浏览能力，直接说明无法完成 `best-of-web`，不要假装已经检索过互联网。
