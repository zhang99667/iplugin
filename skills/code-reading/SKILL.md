# 带我读代码

## 目标

帮助用户从头到尾、逐步详细地理解一段代码的完整执行链路。重点是把"创建 → 初始化 → 事件注册 → 触发 → 分发 → 回调"的每一步都讲清楚，让不熟悉这段代码的人也能完全理解。

## 工作流程

### 1. 确定入口
- 先找到用户关心的代码入口文件/类
- 读取完整源码

### 2. 追踪继承链
- 如果涉及继承，找到父类/接口
- 读取父类中相关方法的实现
- 明确哪些逻辑在子类，哪些在父类

### 3. 追踪创建过程
- 找到关键对象是在哪里创建的（new / inflate / findViewById）
- 说明创建的时机（构造函数 / init / setData / 某个生命周期）
- 如果是 View，说明它来自哪个布局 XML

### 4. 追踪事件注册
- 找到 setOnClickListener / 回调注册 / EventBus 注册的位置
- 说明注册时机和触发条件

### 5. 追踪事件分发
- 从用户触发（点击/滑动等）开始
- 逐步跟踪每一层调用
- 标注每一步所在的文件和行号

### 6. 画出完整流程图
- 用 ASCII 流程图或层级结构展示完整链路
- 标注关键文件名和行号

## 输出格式要求

### 必须包含的内容：
1. **入口说明** - 从哪个文件、哪个方法开始
2. **逐步拆解** - 每一步都标注：
   - 文件路径（简写）
   - 行号
   - 代码片段（关键几行）
   - 这一步做了什么（用中文解释）
3. **对象来源说明** - 对于关键变量/对象，说明它是在哪里创建的、什么类型
4. **完整流程图** - 最后用 ASCII 图总结

### 格式示例：

```
### 第X步：XXX

文件：`SomeClass.java` 第N行

（贴关键代码）

**解释**：这一步做了...，其中 `someVar` 是在第Y步创建的...
```

## 输出阶段

分析完成后，判断用户意图决定输出方式：

- 用户要求"生成报告"、"写成HTML" → 调用 Skill("html-report") 交给它生成 HTML 报告
- 用户只是问代码逻辑 → 直接在终端输出 Markdown 结论
- 不确定时 → 主动问一句"需要生成 HTML 报告还是直接输出结论？"

## 注意事项

- 不要假设用户了解代码，每个关键对象都要说明来源
- 如果某个变量/方法来自父类或其他文件，必须追踪过去看
- 遇到接口回调，要说明"谁设置的回调"和"什么时候被触发"
- 遇到 EventBus，要说明"谁发的事件"和"谁收的事件"
- 如果发现某条路径实际无效（如 listener 为 null），要明确指出
