# 项目/需求总结整理

## 触发边界

当用户希望把一个已完成或阶段性完成的工作整理成总结时，使用本技能。

### 适用

典型输入包括：需求背景、项目目标、个人负责范围、实施过程、技术或协作难点、解决方案、结果收益、风险/遗留问题/后续计划、相关卡片/提交/代码路径、用户口述的零散素材。

### 不适用

用户只是要求普通对话摘要、代码逻辑解释、会议纪要、日报周报、HTML 报告或晋升材料包装时，不使用本技能。

### 需要确认

如果用户说"总结一下"但对象不明确，先判断是否是项目/需求/Bug/技术改造总结；如果只是上一轮回答摘要，直接简短总结，不触发本技能。

目标是写得**清楚、可信、精简、方便回看和复用**，不是写得"高级"。

## 核心工作流

1. 读取用户提供的素材（文件、对话内容、口述）。
2. 识别：这是什么项目/需求？用户完成了什么？核心难点和结果是什么？
3. 按标准模板整理输出（见下方模板，详细写作规范见 `references/writing-guide.md`）。
4. 用户说"简单点""几条就够"时切换为简短版（见 `references/writing-guide.md`）。

## 标准模板

```markdown
## [项目或需求名称]

**背景与目标：**  
**完成内容：**  
**关键难点：**  
**结果与收益：**  
**经验沉淀：**  
```

如有遗留问题或后续事项，追加：

```markdown
**后续事项：**  
```

## 默认输出约定

- 默认输出一版，不给太多备选。
- 不解释"我是怎么整理的"，直接给最终总结。
- 不改变事实，不编造数据，不把"参与"写成"主导"。

## Progressive Disclosure

需要详细写作原则、语言规范、示例参考或简短版要求时，读取：
