# SVG 技术图风格系统

## 默认定位

默认画“朴素、清楚、像技术文档里应该出现的图”，而不是暗色科技感海报。优先让读者看懂结构、方向和差异。

默认风格：

- 白底或浅灰底。
- 灰阶线框为主。
- 少量强调色只用于主流程、风险、成功、外部依赖等必要语义。
- 不使用霓虹、强渐变、发光、复杂阴影和装饰性背景。
- 不把调色盘当成硬约束；调色盘只是为了避免临时乱选颜色。

## 推荐色彩

先使用中性色，再按需要加 1 到 3 个强调色。

中性色：

| 用途 | 色值 |
| --- | --- |
| 页面背景 | `#FFFFFF` |
| 轻背景 / 分组底 | `#F8FAFC` |
| 分隔背景 | `#F1F5F9` |
| 主文字 | `#0F172A` |
| 正文 | `#334155` |
| 辅助文字 | `#64748B` |
| 边框 / 连接线 | `#CBD5E1` |
| 次级连接线 | `#94A3B8` |

可选强调色：

| 用途 | 色值 | 使用建议 |
| --- | --- | --- |
| 主流程 / 当前重点 | `#2563EB` | 一张图最多一条主路径 |
| 成功 / 推荐 / 完成 | `#16A34A` | 只标结论或目标状态 |
| 关键 / 注意 | `#D97706` | 决策点、关键约束 |
| 风险 / 错误 | `#DC2626` | 异常路径、阻断、反例 |
| 外部系统 / 扩展 | `#7C3AED` | 第三方、可选能力、平台层 |

色彩规则：

- 能用黑白灰讲清楚，就不要加颜色。
- 一张图优先只用 1 个强调色；确实有风险/成功对照时最多 3 个。
- 同一篇文章中，相同语义尽量复用同一强调色。
- 不用大面积彩色填充；更推荐细边框、左侧短色条、标题小标签或箭头颜色。
- 如果上游 HTML 报告已有视觉系统，可借用它的主色，但仍保持少色。

## 字体和字号

字体栈：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans CJK SC", "Segoe UI", sans-serif;
```

字号底线：

- 主标题：`24px` 到 `30px`，最低 `22px`。
- 副标题 / 说明：`13px` 到 `15px`。
- 节点标题：`15px` 到 `17px`。
- 节点正文：`13px` 到 `15px`，最低 `12px`。
- 小标签 / 编号：`11px` 到 `12px`，只放短词。

文字规则：

- SVG 文本不自动换行，必须手工用 `<tspan x="..." dy="...">` 分行。
- 中文估宽按 `字数 * 字号`；中英混排按更保守的中文宽度估算。
- 节点内左右 padding 至少 `16px`，标题和正文间距 `8px` 到 `12px`。
- 编号和标题之间的视觉距离不超过 `30px`，避免标题像脱离了步骤。

## 文字占位预算

写坐标前先给每个文字块做粗略包围盒，尤其是节点正文、箭头标签、图例和底部说明。不要等渲染后才靠肉眼挪几个像素。

估算规则：

```text
可用宽度 = 容器宽度 - 左右 padding
中文单行宽度 ≈ 字数 * 字号
英文单行宽度 ≈ 字符数 * 字号 * 0.58
正文行高 ≈ 字号 * 1.45
文本块高度 ≈ 行数 * 行高
```

节点内：

- 标题基线到正文第一行基线至少 `28px`，标题较长或带编号时增加到 `32px`。
- 正文最后一行基线必须早于节点底边至少 `20px`，避免文字贴边或被边框压住。
- `14px` 正文推荐 `dy="21"`；`13px` 正文推荐 `dy="19"`；不要为了塞内容把行距压到 `16px` 以下。
- 预计正文超过 3 行时，优先删字、拆节点或增高节点，不要缩字号到不可读。

节点外：

- 底部说明、图例、角标、箭头标签都算独立文本块，必须放进明确预留的注释区或箭头通道。
- 底部说明的首行基线至少满足：`baselineY >= 最低节点或箭头底部 + 24px`。
- 底部说明最后一行下沿必须早于画布底边至少 `40px`。空间不够时扩大 `viewBox` 高度或上移主体，不要把说明文字压进节点边框附近。
- 箭头标签与线条至少 `8px` 到 `12px`，与节点边框至少 `16px`；长标签拆行或移到旁侧说明。

## 画布和节点

画布按内容选择，不固定套同一个尺寸。默认流程是先摆内容，再用内容包围盒反推画布：

- 技术长文横图：`viewBox="0 0 1200 675"`，只适合有上下两层、分组容器或较多内容的图。
- 单行流程、生命周期、横向 3 到 6 个节点：优先使用较矮画布，例如 `viewBox="0 0 1200 360"` 到 `1200 460`。
- 信息更密集的报告图：`viewBox="0 0 1200 720"`，只在确实需要更多垂直信息时使用。
- 竖向流程：`viewBox="0 0 900 1100"` 或按步骤数扩展高度。
- 背景 `<rect>` 的宽高必须和 `viewBox` 对应；内容完成后根据最上/最下元素再裁掉多余空白，保留外边距即可。

自适应画布计算：

1. 统计所有真实内容的包围盒，不包括背景 `<rect>` 和预留空白。内容包括标题、副标题、节点、分组容器、箭头、marker 可见延伸、箭头标签、图例和底部说明。
2. 得到 `contentMinX/contentMinY/contentMaxX/contentMaxY` 后，选择外边距：普通报告图 `40px` 到 `56px`，公众号或独立长图 `48px` 到 `72px`。默认不要超过 `72px`。
3. 优先把内容整体平移到从外边距开始，然后使用 `viewBox="0 0 W H"`：
   - `W = contentWidth + marginLeft + marginRight`
   - `H = contentHeight + marginTop + marginBottom`
4. 如果不想平移内容，也可以使用非零起点 `viewBox="minX minY W H"`，但背景 `<rect>` 必须写同样的 `x/y/width/height`，不能只写 `width/height`。
5. 任一侧外部空白超过 `96px` 或超过对应画布方向的 `12%`，视为画布未自适应，必须裁短 `viewBox`、缩小宽高或整体移动内容。
6. 横向 3 到 6 个节点不要求固定 `1200` 宽；如果内容实际只需要 `960px` 到 `1080px`，就使用更窄的 `viewBox`。

垂直平衡规则：

- 先把画布拆成标题区、主体区、说明区三个 band，再放节点；不要先把节点贴到上半屏，最后把剩余空白留在底部。
- 完成坐标后计算主体包围盒：`mainTop` 是节点、箭头和关键标签的最小 y，`mainBottom` 是最大 y；不把外边距和空白背景算进主体。
- 若没有底部说明，`bottomWhitespace = viewBoxHeight - mainBottom`；若有底部说明，用 `noteTop - mainBottom` 检查主体和说明之间的间距，再用 `viewBoxHeight - noteBottom` 检查画布底边。
- 对横向单行图，主体上方空白和主体下方空白差异不应超过 `80px`；下方空白超过上方空白 2 倍时，必须下移主体或裁短画布。若底部只有一句说明，说明最后一行到画布底边保留 `40px` 到 `56px` 即可，不要留下更大的空白。
- 顶部有请求路径、阶段标签或红框标注时，为它们单独预留 `32px` 到 `56px` 的 band；它们不能和标题、节点顶边或分组容器挤在同一行。

布局间距：

- 外边距：至少 `40px`，标题区下方至少 `28px`。
- 并列节点间距：至少 `28px`，复杂箭头通过的 gutter 至少 `36px`。
- 多条箭头需要共享通道时，gutter 至少 `52px`；不足时必须增加汇聚节点、改成分层/泳道或删减节点宽度。
- 节点圆角：`6px` 到 `8px`。普通架构图不需要大圆角。
- 阴影：默认不用；如果需要层级，只用非常轻的阴影。
- 分组容器：浅灰底或虚线边框即可，不做厚重面板。

节点结构：

1. 白色或浅灰矩形。
2. 细边框。
3. 可选编号、小标签或左侧短色条。
4. 标题。
5. 1 到 3 行正文短句。

## 连线通道和汇聚层

SVG 不会理解“节点不能被线穿过”，所以连线通道必须在布局阶段设计出来：

- 3 条以上输入指向同一个现象、结论或策略时，先放一个中间汇聚层，例如“变量池”“归因混杂”“证据不足”“统一判定”。多输入只连到汇聚层，汇聚层再用单箭头连接目标。
- 不要让多条曲线的终点落在同一个 `40px` 见方区域；如果语义上确实汇聚，应该用汇聚节点表达，而不是用线条叠加表达。
- 箭头优先走节点之间的水平/垂直 gutter。斜线只有在不会穿过节点、标题、正文、标签时才使用。
- 右侧节点和目标节点之间没有足够通道时，先改结构，不要从节点中间斜穿过去。
- 对复杂汇聚图，先画“变量 -> 汇聚层 -> 现象 -> 策略”的主干，再补输入节点；不要从每个输入直接连最终目标。

## 可读性底线

- 不使用负字距。
- 不用低对比度浅灰正文。
- 不把文字放在复杂背景上。
- 不用 8 个以上节点挤在一屏；信息过多时拆成多张图。
- 不用过细线条。边框至少 `1px`，主箭头至少 `2px`，重要箭头 `2.5px`。
- 不为了“高级感”添加渐变、光效、背景纹理或大面积色块。
