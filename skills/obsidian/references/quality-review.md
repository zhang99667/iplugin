# 分轮审校与完成标准

审校范围默认是完整交付物，而不只是连续正文：标题、段落、列表、表格、引用块、作者新增的代码注释、图片说明和 SVG 文字都要进入检查。逐字引用保留原文，只检查引用是否准确、是否需要上下文；外部代码只审本次新增或改写的注释。

## 第一轮：合同覆盖

- 每个核心判断是否映射到明确章节。
- 是否出现未在合同中的大段新范围。
- 非目标是否意外进入正文。
- 修改后的结论是否仍与证据一致。

## 第二轮：证据与准确性

- 代码、字段、命令、日期和版本是否可复查。
- “最新”“当前”“通常”“很多”等词是否有依据。
- 强判断是否对应已验证证据；推断是否展示必要推理链。
- 待确认项是否仍保持不确定措辞。
- 外部链接是否指向原始或权威来源。

## 第三轮：结构编辑（强制）

- 用户指定参考文章时，style profile 是否在提纲前完成，成稿是否采用了约定的结构规律且没有照搬原文。
- 概念是否按 knowledge map 的依赖顺序出现，术语是否先定义后使用。
- 每个必须知识点是否覆盖完整且只有一个主章节；其他章节是否只引用，没有重复展开同一结论。
- 标题是否准确命名对象、关系或机制；结构、原理、安全和排错是否优先使用名词性标题。
- 是否有遗漏、重复章节、空壳标题、背景堆积和无效总结。
- 段落、列表、表格和图是否承担合适职责，图后是否点明结论。

技术笔记与公开文章必须执行本轮。旧文反馈暴露结构性或系统性缺陷时，无论篇幅长短也执行。发现问题时先改大纲和主章节归属，再移动或删除正文；没有通过本轮，不进入文风轮。

## 第四轮：文风编辑（强制）

- 保留用户个人语境、术语习惯和已有判断。
- 逐项检查 [style-and-format.md](style-and-format.md) 中的口播风险表达，以及无必要的“你可以……”。
- 删除空转过渡句、口号式对比、同义反复、均匀句式和过度完整的模板结构。
- 评价性判断必须说明条件和依据；无法补足时改成中性事实或明确不确定性。
- 改写只增强清晰度，不擅自增强事实力度或改变立场。
- 旧文改写后检查 diff，确认无关内容没有被删除或重排。

技术笔记与公开文章必须执行本轮；旧文反馈暴露同类文风问题时，无论篇幅长短也执行。文风轮要从文件开头扫描到结尾，并检查表格、引用块、作者新增代码注释和 SVG 文字，不能只搜索正文段落或抽查几个标题。

## 第五轮：格式与发布

- front matter 字段与发布形态匹配。
- 没有一级标题、占位值和错误标题层级。
- 双链和图片路径真实可用。
- 文末有 `---` 和 `## 相关笔记`。
- 项目 validator 和 Git hook 通过。

## Reader test

公开文章和较长技术笔记执行一次独立读者测试。给一个没有当前会话背景的新 Agent 仅提供最终正文，并让它：

1. 回答 3 到 7 个读者最可能提出的问题。
2. 标出无法从正文回答的问题。
3. 找出歧义、隐含前提、术语未定义和内部矛盾。
4. 用一句话复述文章主张和适用边界。

问题控制在 3 到 7 个，不嵌套启动更多审稿 Agent，也不为同一版本重复派发测试。新 Agent 不可用、调用失败或没有返回时，立即回退：暂时隐藏写作合同和会话材料，只根据最终正文完成同一组问题，并在交付中说明没有完成真正的独立上下文测试。

如果读者测试依赖作者口头补充才能通过，说明正文仍缺上下文。修复问题章节后可只重测 reader test 的失败问题，不重复派发整轮 reader test；但结构编辑、文风编辑和自动校验仍要重新执行。不要把测试解释直接附到正文后面。

## 用户反馈后的全篇回归

用户点名某一节、某个标题或某句话时，先判断它是孤立错误还是一类系统性缺陷。编辑仍遵循必要最小范围，但审查不能局限在点名位置：

1. 提取反馈对应的缺陷类型，例如口播标题、术语不一致、无依据判断或重复结论。
2. 扫描全文和关联 SVG 的所有文字载体，列出同类命中。
3. 只修改确认存在问题的部分，保留未涉及的事实、元数据和原始语气。
4. 重新执行结构轮、文风轮、图片链接与发布校验。

“只复查 reader test 的失败问题”只限制重新派发 reader test，不限制全文同类缺陷扫描。

## 完成标准

只有同时满足以下条件才能交付：

- 写作合同覆盖完整，正文没有越界。
- 关键判断有证据、例子或明确推理。
- 陌生读者能理解文章承诺和边界。
- front matter、Obsidian 格式、双链和附件正确。
- 没有占位符、模板句和未说明的不确定事实。
- 用户反馈触发的同类缺陷已完成全篇与关联 SVG 回归。
- 本地图片链接有效，图文术语与事实一致。
- 所有自动校验通过。
