# 写作模式

## 快速笔记

适用于一个结论、一条命令、一次短排查、会议结论或以后可能检索的经验点。

流程：

1. 用 brief-lite 确认问题、结论、依据和非目标。
2. 没有时间敏感事实时，不为补齐形式做大规模外部研究。
3. 使用 2 到 5 个小节说清楚，不硬凑背景、历史、FAQ 和展望。
4. 写完立即执行 front matter 与结构校验。

如果证据出现多个冲突来源、需要解释完整链路，或正文自然增长为多个独立论点，升级为技术笔记。

## 工作模式与文档类型

工作模式回答“这次如何生产和交付”，文档类型回答“内容按什么认知结构组织”。`type: note` 可以是一篇完整技术指南，`type: post` 也可以是一篇问题复盘；不要用发布形态代替内容分类。

## 文档类型

根据读者任务选择内容结构：

| 类型 | 读者任务 | 常见结构 |
| --- | --- | --- |
| 快速记录 | 保存一个结论、命令或经验点 | 问题/场景 → 结论 → 必要依据 |
| 教程 | 从不会到完成一次学习体验 | 前置条件 → 分步实践 → 可见结果 → 下一步 |
| How-to | 解决一个明确问题 | 目标 → 条件 → 操作 → 验证 → 故障处理 |
| 参考 | 快速查字段、接口、命令或配置 | 范围 → 条目 → 参数/约束 → 示例 |
| 原理说明 | 建立机制和关系认知 | 定位 → 边界 → 机制 → 取舍 → 影响 |
| 问题复盘 | 记录现象、根因与防复发措施 | 现象 → 结论 → 根因链 → 验证 → 修复/预防 |
| 完整技术指南 | 让陌生读者从定义走到实现、设计和排错 | 定义与边界 → 为什么需要 → 最小可运行示例 → 组成部分 → 加载和运行机制 → 不同产品中的实现 → 设计、安全与排错 |

快速记录固定使用快速笔记模式。其他类型可以是私有技术笔记，也可以按发布目标成为公开文章；不要把教程步骤、参考手册和概念解释混成一篇。确实需要组合时，先确定主类型，其他内容只作为支撑章节。

技术笔记使用 full brief，要求每个核心判断绑定代码、日志、配置、官方资料、已有笔记或清晰推理。大纲先覆盖判断，再开始正文。

### 完整技术指南

“完全指南”“完整指南”“从零到深入”或同等承诺使用完整技术指南类型，不因它最终是私有 note 还是公开 post 而改变概念依赖。

默认依赖链为：

```text
定义与边界
→ 为什么需要
→ 最小可运行示例
→ 组成部分
→ 加载和运行机制
→ 不同产品中的实现
→ 设计、安全与排错
```

这不是要求机械复制七个标题，而是要求知识按该依赖关系可被读者建立。主题不涉及产品差异、安全或运行机制时，可在写作合同中说明删减理由；不能无说明跳过已向读者承诺的部分。

完整指南使用专业参考文档结构。个人经历只有在提供证据、设计动机或排错价值时才保留，不为了“个人感”加入“以后你遇到”“你可以先”之类叙述。

## 公开文章

公开文章对应 `type: post`，默认面对不了解当前会话和个人工作背景的读者。

1. 明确读者、文章承诺、独特角度和读完后的行动或认知变化。
2. 形成 full brief 和判断—证据矩阵；方向存在实质分歧时，先让用户确认大纲。
3. 把必要背景写进正文，个人上下文只保留对读者有价值的部分。
4. 完成独立 reader test，确保陌生读者能回答文章承诺的问题。
5. 执行发布门禁：来源、日期、summary、tags、真实链接和占位符全部检查。

SEO、营销 CTA 和关键词密度不是默认目标。只有用户明确要求站点流量或转化时才加入，不能挤占技术准确性和文章价值。

## 旧文改写

旧文改写先列出三类约束：

- **必须保留**：用户原结论、个人经历、有效的已有链接、未知 front matter 字段。
- **允许改变**：用户点名的段落、过期事实、局部结构和表达问题。
- **明确不动**：无关章节、图片布局、文件名和目录，除非任务要求。

优先做局部替换，不整篇重写。历史坏图和失效本地附件不属于“必须保留”：能从现有资产确定目标时修复路径，确认无内容价值时移除引用，无法判断原意时保留现场并向用户说明阻塞，不能让严格校验静默通过。修改后检查 diff，确认没有悄悄删除原始信息、改变语气或扩大事实强度。旧文缺少 front matter 时，无法判断发布形态就保守补：

```yaml
---
publish: false
type: note
topic: <稳定主题>
---
```

## 模式切换

- 快速笔记出现三个以上独立核心判断或复杂证据链时，升级为技术笔记。
- 技术笔记需要进入博客流、面向陌生读者解释完整背景时，升级为公开文章。
- 用户只要求修订现有内容时，始终走旧文改写，不自动升级为全新长文。
