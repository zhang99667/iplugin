# 写作合同与证据映射

写作合同用于约束最终内容，不是展示给读者的固定章节。

## Brief-lite

快速笔记在动笔前确认六项：

```markdown
- 模式：快速笔记
- 要回答的问题：
- 核心结论：
- 依据：
- 非目标：
- 目标路径：
```

如果“核心结论”或“依据”无法写清，先缩小问题或补证据。

## Full brief

技术笔记和公开文章使用：

```markdown
## 写作合同
- 模式：技术笔记 / 公开文章
- 文档类型：教程 / How-to / 参考 / 原理说明 / 问题复盘 / 完整技术指南
- 目标读者：
- 读者已知：
- 要回答的问题：
- 预期影响：
- 非目标：
- 未知与不确定项：
- 目标文件：

## 核心判断
- C1：
- C2：
- C3：

## 证据
- E1：来源、日期/版本、关键事实
- E2：来源、日期/版本、关键事实

## 覆盖矩阵
| 判断 | 证据 | 正文章节 | 状态 |
| --- | --- | --- | --- |
| C1 | E1 | 章节名 | 待写 |

## 完成标准
- [ ] 每个核心判断至少有证据、例子或显式推理。
- [ ] 每个章节都服务至少一个核心判断或必要读者任务。
- [ ] 非目标没有进入正文。
- [ ] 不确定项没有被改写成确定事实。
```

核心判断控制在 3 到 7 个。超过 7 个通常意味着主题过大，应拆文或缩小范围。

## 指定参考文章时的 Style profile

用户指定一篇或多篇参考文章时，必须在列提纲前读取全文并补充以下工件：

```markdown
## Style profile
- 参考文章：
- 标题形式：标题如何命名对象、关系或问题
- 章节展开顺序：各章节如何承接，先决概念如何出现
- 段落密度：常见段落长度、解释与示例比例
- 列表和表格：分别在什么信息结构下使用
- 配图节奏：图片出现位置、图前说明和图后结论
- 语气与叙述视角：专业程度、人称、判断强度
- 可以借鉴：结构、节奏、信息组织等可迁移规律
- 不能照搬：原文措辞、独有观点、案例、事实和装饰性习惯
```

style profile 是条件必做工件，不是“读过参考文”的口头确认。提纲要能逐项说明采用或不采用哪些规律；参考文章与用户明确要求冲突时，以用户要求为准，并在 profile 中记录偏离原因。

## 完整技术指南的 Knowledge map

完整技术指南在核心判断之外维护知识点地图。核心判断用于约束文章主张，knowledge map 用于约束认知顺序和覆盖面，两者不能互相替代。

```markdown
## Knowledge map
| 知识点 | 读者先决知识 | 唯一主章节 | 其他章节允许的引用 | 状态 |
| --- | --- | --- | --- | --- |
| 定义与边界 | 无 | 定义与边界 | 后文只引用，不重新定义 | 待写 |
| 最小可运行示例 | 定义、问题背景 | 最小可运行示例 | 实现章节可引用结果 | 待写 |
```

进入正文前检查：

- 每个必须知识点都有且只有一个主章节。
- 章节顺序满足先决关系，不在定义前使用未解释术语。
- 同一结论不在定义、架构图、选型和总结中分别重新展开；非主章节只做带链接或明确指向的短引用。
- 知识点没有证据时标为待确认或移出承诺，不能用常识补成新事实。

## 证据等级

按可靠性使用证据：

1. **已验证**：代码、运行结果、官方文档、原始资料直接支持。
2. **可信推断**：多个事实能推出结论，但没有直接声明；正文说明推理链。
3. **待确认**：线索不足或来源冲突；正文明确标注，不用于强结论。

二手文章可以帮助发现问题，但重要技术判断应尽量回到代码、标准、官方文档或原始研究。

## 进入成稿的条件

满足以下条件才开始长文：

- 问题和目标读者明确。
- 核心判断没有互相矛盾。
- 每个核心判断至少有一个证据槽位，或明确标注待确认。
- 非目标和目标文件已确定。
- 大纲能把每个核心判断映射到具体章节。
- 用户指定参考文章时，style profile 已完成。
- 完整技术指南的 knowledge map 已通过唯一主章节和先决关系检查。

成稿完成后回查覆盖矩阵，把状态更新为“已覆盖”“证据不足”或“删除”。改写导致判断或证据变化时，先更新合同，再修改正文。
