# v0.8.0 结构化询问命令

## 目标

新增一个手动调用入口，让用户在需求歧义、UI 方案、实现分支或风险操作不确定时，可以主动把决策点交给 AskUserQuestion / request_user_input。

## 变更清单

- 新增 `ask-user-question` skill。
- 新增 `/askuserquestion` slash command，并提供 `/ask-user-question` 别名。
- 插件版本从 `0.7.0` 升级到 `0.8.0`。
- 更新 Claude Code 与 Codex manifest 的描述和关键词。
- 更新 README 和 CHANGELOG。
- 更新开发准则：文件改动完成并校验后，通过 `/ask-user-question` 询问用户是否提交本次改动。
- 更新开发准则：`CLAUDE.md` 与 `AGENTS.md` 作为同源维护指南同步修改。

## 架构决策

- skill 保持手动调用，不作为普通需求的主动触发器，避免频繁打断执行流。
- slash command 作为主要入口，命令文件只负责把 `$ARGUMENTS` 和最近上下文交给 skill。
- 结构化询问工具可用时优先使用；不可用时退化为普通文本选择题，避免假装已经弹出选择 UI。
- 每次只问一个最关键问题，选项限制为 2 到 3 个，推荐项放第一位。
- 提交动作仍由用户显式确认触发；完成改动后先询问是否提交，避免自动创建用户未确认的 commit。
- `CLAUDE.md` 与 `AGENTS.md` 的差异只允许来自明确平台原因；普通维护规则必须双文件同步。

## 排除项

- 不实现新的 AskUserQuestion 工具。该版本只沉淀调用规范，依赖当前宿主环境提供的结构化询问能力。
- 不改全局行为为“遇到不确定就问”。需要该行为时由用户显式调用命令。
