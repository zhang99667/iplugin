# v0.8.9

## 目标

优化 `html-report` 的代码变更展示能力，让 HTML 报告中的新增、删除、修改和上下文一眼可分辨，避免修复方案里混入旧代码却看不出改动位置。

## 变更清单

- `html-report` 升级到 `0.2.8`
  - 核心原则增加“涉及代码新增、删除或修改时必须使用变更标识”
  - 内容规则要求代码变更报告明确区分新增、删除、修改和上下文
  - 视觉规则新增“代码变更标识”章节，定义聚焦 diff、Before/After 双栏、新增代码块和删除代码块的适用场景
  - CSS 模板新增 `change-chip`、`diff-card`、`diff-table`、`diff-add`、`diff-del`、`diff-mod`、`diff-mark-add`、`diff-mark-del` 等样式
  - 修正 HTML 骨架里的文件定位示例，要求路径和行号范围合并为一个可跳转 IDEA chip
- 插件版本升级到 `0.8.9`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- 代码变更报告优先使用聚焦 diff，而不是只贴“当前代码”和“修复方案”，因为读者最关心的是具体变更点。
- 行级修改优先拆成相邻的删除行和新增行；行内小改可以使用 `<del>` / `<ins>` 或对应 class 标出 token 变化。
- 如果展示的是建议方案而非真实 git diff，必须标成“建议变更”或“拟修改”，避免误导读者以为它已经发生。
- 文件定位必须优先展示可读的相对路径和完整行号范围，跳转链接使用绝对路径和起始行；不要把路径和行号拆成两个 chip。

## 排除项及原因

- 不引入第三方 diff 渲染库：HTML 报告保持单文件输出，当前需求只需要稳定的视觉规范和可复用 CSS。
- 不改变 html-report 触发边界：本次只优化报告内部的代码变更表达。
