# v0.21.6 - delegated-search 委派条件放宽

## 目标

修正 `delegated-search` 中“强阈值”表述过硬的问题，让复杂任务委派更贴近实际 Agent 工作流：先做委派判断的门槛要低，真正创建子 Agent 时再根据独立性、自包含程度、上下文收益和平台规则决定。

## 变更清单

- `skills/delegated-search/SKILL.md`
  - skill 版本升级到 `0.1.4`。
  - 将“强阈值”章节改为“委派信号”。
  - 明确数字只是帮助估算上下文压力的参考，不是硬门槛。
  - 增加更通用的委派信号：用户明确要求拆子 Agent、存在 2 个以上可独立推进的子问题、子任务会产生大量中间输出、子任务可以自包含完成、需要专门角色或权限边界。
  - 将“不委派说明”的条件从命中强阈值调整为命中委派信号但判断不委派。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.6`。
- `CHANGELOG.md`
  - 新增 `0.21.6` 版本记录。

## 架构决策

- 不保留“强阈值”术语。数字阈值容易让 Agent 误以为低于数量就不能委派，而实际目标是更早识别复杂任务并判断是否拆分。
- 保留数字作为复杂度信号。文件数、目录数和输出行数仍能帮助识别上下文风险，但只作为参考，不决定最终是否委派。
- 不调整 README 和默认提示。对外能力定位仍是复杂任务委派，本次只是细化内部触发条件。

## 排除项及原因

- 不重新改名 `delegated-search`。名称兼容问题已在 v0.21.5 记录，本次只修正条件强弱。
- 不新增 eval workspace。当前修改是对用户直接反馈的局部规则修正，后续若要评估触发率，再单独做 trigger eval。
