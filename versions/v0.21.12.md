# v0.21.12 - generate-image 密钥缓存复用

## 目标

优化 `generate-image` skill 的首次鉴权体验：用户第一次提供图片 API 令牌后，应保存到本机私有缓存，后续生成图片时自动复用，不再每次触发 `ask-user-question`。

## 变更清单

- `skills/generate-image/scripts/generate_image_client.py`
  - 新增默认 key 缓存路径 `~/.config/iplugin/generate-image-api-key`。
  - `_read_api_key` 在环境变量和显式 key 文件之后读取默认缓存。
  - 新增 `--save-api-key-stdin`，从 stdin 保存令牌，避免 key 出现在命令行参数里。
  - 新增 `--save-api-key-only`，允许只保存令牌不生成图片。
  - 保存 key 文件时使用 `0600` 权限。
- `skills/generate-image/SKILL.md`
  - skill 版本升级到 `0.1.4`。
  - API key 流程改为首次直接粘贴并保存，后续复用缓存。
  - 认证失败或缓存过期时重新询问并覆盖缓存。
- `skills/generate-image/references/generate-image-apis.md`
  - 同步默认缓存路径和 stdin 保存方式。
- `README.md`
  - Skills 表同步说明 API key 首次提供后本地缓存复用。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.12`。
- `CHANGELOG.md`
  - 新增 `0.21.12` 版本记录。

## 架构决策

- 默认缓存放在用户配置目录，而不是仓库目录，避免令牌进入 git 工作区、prompt、版本记录或命令行历史。
- 保留环境变量和显式 key 文件的优先级，方便 CI、临时覆盖和已有用户配置继续工作。
- 使用 stdin 保存粘贴令牌，不新增把令牌作为 CLI 参数传入的能力。
- 认证失败时不自动删除缓存，只要求用户刷新并覆盖，避免误删用户手动维护的 key 文件。

## 排除项及原因

- 不接入系统钥匙串。当前脚本保持标准库实现，减少跨平台和交互授权复杂度。
- 不加密缓存文件。缓存位于用户配置目录且权限设置为 `0600`，足够覆盖当前个人研发工作流。
- 不改变图片生成 API 请求结构。本次只优化鉴权缓存和 skill 引导流程。
