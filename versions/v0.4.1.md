# v0.4.1

## 目标

补充 iCafe 需求交付归档流程：每次整理目标文件夹时检查是否已有总结，避免交付材料只有原始需求和详设、不方便后续快速回看。

## 变更清单

- `icafe-delivery-archive` 升级到 `0.1.1`
- 归档产物增加可选的 `总结 · <space>-<sequence>.md`
- 明确总结存在性判断规则：文件名包含“总结 / 复盘 / summary / retrospective”的 `.md`、`.html`、`.docx`
- 目标目录没有总结时，要求调用 `project-summary` 生成总结内容并写入文件
- 推荐脚本片段增加总结缺失检测输出 `NO_SUMMARY:`

## 架构决策

- 总结生成复用已有 `project-summary` skill，避免在归档 skill 中重复定义总结写作风格。
- 已有总结不覆盖、不重复生成，避免破坏用户手工沉淀内容。
- 总结使用 Markdown，和 HTML 需求描述区分：HTML 保存原始富文本，Markdown 保存二次提炼。

## 排除项

- 不强制重写历史总结。
- 不把总结内容打印到对话里，最终只报告文件路径和生成状态。
