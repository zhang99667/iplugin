# v0.11.3

## 目标

优化 `html-report` skill 的触发描述和触发边界，让它既能响应用户明确的 HTML 请求，也能在复杂交付物场景中自动判断是否应生成 HTML。

## 变更清单

- `skills/html-report/SKILL.md` 升级到 `0.2.12`。
- 重写 `html-report` frontmatter `description`：
  - 明确 HTML 请求或 `/htmlreport` 调用时必须触发。
  - 增加复杂交付物自动触发条件。
  - 明确其他 skill 可在复杂报告、交付物、归档材料场景调用本 skill。
  - 保留普通简短总结、整理、结论默认 Markdown 的反触发边界。
- 调整 `触发边界` 和 `最短执行流程`：
  - 将“适用”拆成显式 HTML、复杂交付物自动判断、其他 skill 调用三类。
  - 将“需要确认”收窄到无法判断输出形态的模糊请求。
- `.claude-plugin/plugin.json` 和 `.codex-plugin/plugin.json` 插件版本升级到 `0.11.3`。
- `CHANGELOG.md` 增加 `0.11.3` 记录。

## 架构决策

- 不把代码评审、问题排查、技术方案等关键词单独视为触发条件；它们只有在报告复杂度和交付物属性成立时才推动 HTML。
- 保持 `html-report` 的职责为“独立 HTML 报告文件”，不接管普通 Markdown 总结。
- 继续允许其他 skill 调用，但要求调用方根据输出形态和内容复杂度做判断，避免所有上游总结都变成 HTML。

## 排除项及原因

- 不修改 `/htmlreport` command：命令入口已经表达显式 HTML 意图。
- 不改视觉模板和内容模板：本次只修正触发与调度边界。
