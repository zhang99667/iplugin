# v0.22.26 - HTML Report 批注手动重新关联

## 目标

当报告正文变化导致批注原有 `blockId` 无法自动定位时，允许用户在当前正文选区上修复锚点，保留原批注交接身份和内容，避免删除后重建造成上下文丢失。

## 变更清单

- 失效批注卡片新增 `重新关联` 入口；进入临时模式后，选区气泡唯一操作切换为 `重新关联`。
- 成功确认只替换 `blockId`、章节、选中文本、块文本和前后文等定位字段，保留原 `id`、`kind`、`text`、`createdAt` 及来源字段。
- 进入重新关联时自动收起侧栏，保证窄屏也能选择正文；`Esc`、卡片取消按钮、正文外/无效选区均安全退出临时模式，不写入批注数组。
- 重新关联后复用现有高亮、localStorage、`完成批注` 保存和 unresolved 定位校验；不引入待处理状态、回复线程或 schema 版本变化。
- 校验器、插件资产门禁、运行时定位测试、组件测试、标准 Gallery 和评论模式 eval 同步更新。
- `html-report` skill 从 `0.7.5` 升级到 `0.7.6`，插件从 `0.22.25` 升级到 `0.22.26`。

## 架构决策

- 采用页面会话级 `rebindAnnotationId`，不把“编辑中”状态写入 `AgentQuestionPack`，避免交接文件出现未完成的协作状态。
- 复用 `buildTargetFromSelection()`，确保新锚点遵守既有 `<main>` 边界、`data-block-id` 和上下文截取规则。
- 使用独立 `buildReboundAnnotation()` 复制对象并替换锚点字段，保留不可变的批注身份/内容字段；只有用户点击选区气泡后才提交。

## 排除项及原因

- 不实现 Figma 式拖动锚点、跨段复杂范围、回复线程、待处理/已处理状态或多人同步；这些会扩大离线单文件 schema 和测试影响面，留待后续独立批次评估。
- 不对无法自动定位的评论做模糊猜测；用户必须显式选择当前正文位置，保存前仍由现有安全校验兜底。
