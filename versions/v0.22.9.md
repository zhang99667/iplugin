# v0.22.9

## 目标

把 FEEDADS-24710 三方代码 Review 报告中验证有效的 Workspace 审阅体验沉淀为
`html-report` 可复用组件，让后续多文件、多版本代码评审不再重复手写业务专用 CSS、
源码 JSON 和交互脚本。

## 变更清单

- 新增 `references/review-workspace.md`，定义多版本审阅组件的适用边界、规格字段、构建流程、安全约束和与标准 diff viewer 的分工。
- 新增 `references/css/review-workspace.css`，提供文件导航、工具栏、多版本源码窗格、标记行、响应式和打印样式。
- 新增 `assets/review-workspace/workspace.js`，支持文件筛选、状态筛选、同步滚动、只看差异、参考行/任意行跳转、全文复制、IDEA 打开和已审阅进度。
- 新增 `scripts/build_review_workspace.py`，从 JSON 规格读取 2 到 3 份源码快照，校验文件/版本/行号契约，复用静态高亮能力，并安全生成内嵌数据和唯一 runtime。
- `check_html_report.py` 新增 Workspace 结构、数据 schema、raw-text 转义、允许的 `tok-*` HTML、唯一 runtime、复制回退、响应式和打印样式检查。
- `scripts/validate-plugin.py` 新增 Workspace runtime、CSS 和构建脚本资产完整性检查。
- 新增两方与三方回归规格、两文件源码 fixture 和 eval，覆盖自动栏数布局、行为变化与 Lite 标记修复场景。
- 同步更新 `SKILL.md`、CSS 装配说明、视觉规则、代码评审模板、README、CHANGELOG 和两个 manifest。

## 架构决策

- Workspace 是代码评审的证据浏览组件，不取代 Findings、合入建议、测试缺口和真实 unified diff。
- 组件只支持 2 到 3 个版本。更多版本会显著增加认知和文件体积，应先收敛到基线、当前和目标版本。
- 不引入 Monaco 或外部高亮库。完整 runtime 与 CSS 内联，源码在生成期使用现有 builtin 高亮，保持单文件离线交付。
- 源码数据不允许由模型手工拼接。构建脚本统一处理 UTF-8 读取、逐行高亮、行号边界和 `<script>` raw-text 安全转义。
- runtime 只接受构建脚本生成的 `tok-*` span；校验脚本拒绝其他源码 HTML 标签，缩小 `innerHTML` 注入边界。
- 已审阅状态只写入 `localStorage`，不承载评审结论或 Agent 交接数据；正式意见仍使用普通正文或评论模式。
- CSS 继续遵循按需装配：Workspace 必须同时使用 `code-diff.css` 和 `review-workspace.css`，普通报告不增加这部分体积。

## 排除项及原因

- 不把 Workspace 设为所有代码评审报告默认组件；小 patch 使用标准 diff viewer 更清晰、更轻。
- 不在本次实现超过 3 个版本、自由拖拽窗格、编辑源码、在线保存或 Monaco 兼容层；这些能力会把离线报告变成简化 IDE，偏离阅读交付物定位。
- 不让 Workspace 生成真实 patch；版本整体浏览与 authoritative unified diff 保持职责分离。
- 不把完整源码无限塞入单文件；规范建议约 20 个文件以内，超出时先缩小范围或拆分报告。
- 不改变离线评论模式的批注包、导出或发布版剥离逻辑。
