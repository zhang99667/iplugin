# v0.19.2 - HTML 报告离线批注审核模式

## 目标

将 HTML 报告原型中验证过的离线批注能力沉淀到 `html-report` skill，使报告可以在本地单文件里完成文本提问/批注，并把问题导出为 Agent 易理解的 Markdown/JSON 提问包。

版本口径：这是已有 `html-report` skill 的新增能力，因此 `html-report` skill 版本从 `0.2.x` 升级到 `0.3.0`；插件层没有新增 skill，插件版本仅按 patch 递增到 `0.19.2`。

## 变更清单

- `skills/html-report/scripts/inject_annotation_mode.py`
  - 新增确定性注入脚本，用于把普通 HTML 报告升级为审核版。
  - 支持选区 `提问` / `批注` 气泡、单按钮 `提交` 输入浮层、右侧批注栏、Markdown/JSON 导出和发布版 HTML 导出。
  - Markdown/JSON 导出写入原 HTML 文件名、绝对路径和 `file://` URL；这些来源路径在生成阶段直接写入批注脚本，运行时 `location` 只作为兜底。
- `skills/html-report/references/annotation-mode.md`
  - 新增批注模式契约，明确交互、发布版剥离、提问包字段和稳定性要求。
- `skills/html-report/scripts/check_html_report.py`
  - 新增批注模式结构校验，防止遗漏路径字段、发布版剥离标记、选区缓存和单按钮浮层。
- `skills/html-report/SKILL.md`、`visual-rules.md`、`css-template.md`
  - 增加批注模式触发、执行路径和模板入口说明。
- README / CHANGELOG / manifest
  - 更新插件能力描述和版本号，插件层保持 patch 升级。

## 架构决策

- 采用“先生成普通 HTML，再运行脚本注入审核模式”的两阶段流程。
- 批注 UI 不作为默认报告能力，只在用户明确需要批注、审核模式或 Agent 提问包时加入。
- 发布版必须物理剥离批注 UI、批注 JS、批注 CSS、批注高亮和本地批注入口，避免对外文档误带内部审核能力。
- Markdown/JSON 提问包必须包含原 HTML 的绝对路径和 `file://` URL，方便主 Agent 或子 Agent 回查上下文。

## 排除项及原因

- 不接入 Hypothes.is、Giscus 等外部评论系统：本地报告常包含内部内容，默认必须离线。
- 不提供后端或 localhost Agent bridge：第一版以 Markdown/JSON 交接最稳，后续可单独设计。
- 不把批注代码复制进 `css-template.md`：交互代码较长，脚本注入更稳定，也避免模板和脚本出现双真源。
