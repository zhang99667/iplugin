# v0.19.10 - Obsidian 个人技术笔记风格规则

## 目标

把用户已有长篇技术笔记中的稳定风格沉淀到 `obsidian` skill：笔记要给自己长期回看，保持高信息密度、边界清楚和解释到位；章节和配图都服务理解，不为了形式完整而扩写。

## 变更清单

- `skills/obsidian/SKILL.md`
  - skill 版本升级到 `0.1.3`。
  - description 补充个人技术笔记写作风格和篇幅控制能力。
  - 新增“写作风格”章节，要求先判断笔记规模，小笔记不套长文模板。
  - 新增“先定位，再展开”规则，要求概念类笔记先讲清位置和边界，版本敏感内容先标更新时间和依据。
  - 新增“用段落解释，用列表收束”规则，避免整篇笔记变成连续 bullet list。
  - 强化配图策略，明确配图只作为理解辅助，图前说明用途，图后点明结论。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.19.10`。
- `CHANGELOG.md`
  - 新增 `0.19.10` 变更记录。

## 架构决策

- 不新增 reference 文件。当前沉淀的是核心写作规则，篇幅可控，直接放在 `SKILL.md` 能让触发后的执行者立即遵循。
- 不把示例长文全文复制进 skill。样例文章只作为风格锚点，skill 中保留可迁移的写作原则，避免上下文膨胀和一次性内容污染。
- 不更新 README 和 manifest keywords。插件对外能力没有新增，只是既有 Obsidian 笔记写作能力的质量规则优化。

## 排除项及原因

- 未新增自动格式化脚本：写作风格判断依赖主题规模和表达意图，当前更适合用规则约束而不是机械改写。
- 未调整 `相关笔记` 收尾规则：这仍是用户现有 Obsidian 文档的稳定格式约定。
