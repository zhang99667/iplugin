# v0.19.1 — HTML 报告接入 SVG 技术图协作

## 目标

让 `html-report` 在生成技术方案、问题排查、代码导读等复杂报告时，能自动借用 `svg-tech-diagram` 生成清晰的内联 SVG 技术图，而不是要求用户同时显式调用两个 skill。

## 变更清单

- `skills/html-report/SKILL.md` 增加 `svg-tech-diagram` progressive disclosure 入口。
- HTML 报告最短执行流程新增复杂技术图路由：先由 `svg-tech-diagram` 生成 SVG、渲染 PNG 并自审，再内联回 HTML。
- `references/visual-rules.md` 新增“SVG 技术图协作”章节，明确适用场景、不适用场景、协作流程和内联结构。
- `references/css-template.md` 新增 `.diagram-block` / `.tech-diagram` 样式，支持图块横向滚动、caption、窄屏和打印降级。
- README 更新 `html-report` 能力描述。
- 插件版本升级到 `0.19.1`，`html-report` skill 版本升级到 `0.2.22`。

## 架构决策

- 采用软依赖：`html-report` 负责报告编排、HTML 样式和最终校验；`svg-tech-diagram` 只负责技术图的信息结构、绘制、PNG 渲染和自审。
- 不新增 slash command，也不要求用户一次调用两个 skill；由 `html-report` 根据内容复杂度判断是否读取绘图 skill。
- SVG 默认内联到最终 HTML，保持单文件离线交付；外部 `.svg` 文件只作为特殊降级方案。
- 不修改 `check_html_report.py`，本次只沉淀协作规则和基础样式，避免把校验面扩大到尚未稳定的图形语义检查。

## 排除项及原因

- 不让 `svg-tech-diagram` 反向依赖 `html-report`：绘图 skill 应保持可独立用于 Markdown、Obsidian 或单独 SVG 交付。
- 不强制每份 HTML 报告都画图：简单结论、表格对比和短流程继续使用更轻的 HTML 结构。
- 不新增自动图形生成脚本：当前价值在于协作流程和人工可审的 SVG 纪律，自动布局后续根据真实使用再评估。
