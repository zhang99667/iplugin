# v0.22.36 - HTML Report 平台化 IDE 跳转

## 目标

让 HTML 报告中的源码定位链接根据技术方案平台统一选择 IDE，避免同一 Android 或 iOS 方案因文件语言不同而混用跳转协议

## 变更清单

- Android 技术方案内所有源码定位默认使用 `idea://open`
- iOS 技术方案内所有源码定位默认使用 `xcode://open`
- IDE 选择不再依赖 Java、Kotlin、Swift、Objective-C 或文件扩展名
- Workspace 顶层 `default_ide` 表示技术方案统一 IDE，混合端报告可用文件级 `ide` 显式覆盖
- 没有技术方案平台信息时兼容回退 IDEA
- Review Workspace 输入新增 `ide`、`ide_line`、`default_ide`，新 runtime 使用 `ideKind`、`ideLabel`、`ideHref`
- 旧 `idea_line` 继续作为输入兼容字段；Builder 新产物只写 `ideHref`，新版 runtime 和校验器继续读取历史报告中的 `ideaHref`
- Workspace 工具栏按当前文件动态显示“IDEA 打开”或“Xcode 打开”
- 校验器对 Workspace 的每个文件验证 `idea://open` / `xcode://open` 协议、绝对路径、起始行、短标签和 title 一致性
- 标准 Gallery 同时展示 IDEA 和 Xcode 文件定位，并使用 iOS 方案下的 Kotlin Workspace 验证路由不依赖源码语言
- 更新组件测试、Gallery 新鲜度门禁和插件资产校验
- `html-report` skill 从 `0.7.14` 升级到 `0.7.15`，插件从 `0.22.35` 升级到 `0.22.36`

## 架构决策

- 文件级显式 `ide` 优先，随后使用技术方案的 `default_ide`，最后回退 IDEA；不读取源码语言或扩展名推断 IDE
- 通用输出字段不再把 IDE 名写死在数据结构中；Builder 只生成 `ideHref`，新 runtime 与校验器以只读方式兼容旧 `ideaHref`
- 普通文件定位与 Review Workspace 共用 `idea://open?file=...&line=...`、`xcode://open?file=...&line=...` 形态，校验器只接受这两类协议
- 本次按用户确认采用 `xcode://open` 作为插件约定。Xcode 26.3 的内置 URL Handler 元数据未声明 `open` host，因此不把该格式描述为 Apple 官方稳定协议，实际可用性取决于使用环境

## 排除项及原因

- 不引入 `file://` 作为 iOS 兜底，因为浏览器打开本地源码不能可靠唤起 Xcode 并定位行号
- 不在 HTML 中尝试执行 `xed --line`，浏览器安全模型不允许普通链接直接运行本地 CLI
- 不移除对旧 `idea_line` 输入和历史 `ideaHref` 数据的读取兼容；新 Xcode 片段若加入旧报告，需要同时重新生成首个 runtime，避免旧按钮继续显示固定 IDEA 文案
- 不修改组件 CSS，文件 chip 的视觉结构与 IDE 协议选择无关
