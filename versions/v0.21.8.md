# v0.21.8 - Android mock 录屏抽帧证据固化

## 目标

把 Android mock 自测中 toast、loading、短暂弹层和“无 toast”这类时序证据的录屏抽帧流程固化到 skill，避免未来只保留 `.mp4` 链接，导致报告读者必须手动播放录屏才能判断 case 结论。

## 变更清单

- `skills/android-mock/SKILL.md`
  - skill 版本升级到 `0.1.3`。
  - 在采证规范中要求时序类录屏生成关键帧或 contact sheet，并与原始录屏一同入报告。
  - 固化 `ffmpeg` 1fps contact sheet 推荐命令，包含 `-frames:v 1`，避免长录屏导致 `tile` 输出多张图时失败。
  - 明确本机缺少 `ffmpeg` 时可以在用户同意后安装，并在报告中记录工具补充。
  - 明确区分业务 toast、系统 toast 和已有调试 toast；调试 toast 只能作为 caveat，不能替代业务 toast 通过证据。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.8`。
- `CHANGELOG.md`
  - 新增 `0.21.8` 版本记录。

## 架构决策

- 继续把 Android mock 的强采证要求放在 `android-mock` skill 中。`html-report` 保持通用媒体证据能力，具体到 Android mock 的录屏抽帧、contact sheet 命名和 toast 判定由调用方 skill 提出。
- 使用 `ffmpeg` 命令作为推荐路径，因为它适合从 adb `screenrecord` 产物中稳定抽取关键帧，且输出 PNG 能直接内嵌到 HTML 报告。
- 仅升级 patch 版本，因为本次是已有验收流程的指令细化，没有新增 skill、command 或用户入口。

## 排除项及原因

- 不新增共享脚本。当前抽帧命令足够短，且不同 case 的录屏位置、窗口长度和 tile 布局可能不同，先保留为 skill 指令。
- 不改 `html-report`。通用报告不应强制所有视频都生成 contact sheet，只有 Android mock 这类验收证据需要强约束。
- 不新增 README 或 manifest 关键词。现有 `android-mock`、`screenrecord`、`video`、`evidence` 等关键词已覆盖这次能力细化。
