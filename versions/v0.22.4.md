# v0.22.4 - HTML 报告批注快捷提交与内嵌交接

## 目标

把 `html-report` 审核模式补成“Agent 生成报告 → 用户在 HTML 内批注 → 保存审核结果到同一类 HTML → Agent 直接读取并更新”的单文件闭环，同时减少连续录入批注时的鼠标操作。

- `skills/html-report/assets/annotation-mode/annotation.js`

  - 新增 `保存审核结果到 HTML`：复用 `AgentQuestionPack`，把审核结果安全内嵌到唯一 `#qaEmbeddedReviewData[data-qa-review-data]` 节点。
  - 重新打开 HTML 时，本地存在更新记录则优先使用；本地 key 不存在、不可用或损坏时从内嵌包恢复批注。
  - 兼容迁移旧版 localStorage 路径键；清空最后一条批注后仍可保存空审核包，确保磁盘旧批注真正被覆盖。

## 架构决策

- HTML 是审核交接的唯一文件载体。`localStorage` 只负责编辑期暂存，Agent 不再依赖用户复制或下载旁路 JSON。
- 当前承载内嵌包的 HTML 是唯一回写目标；包内 `source` 是生成来源元数据，另存后不能据此改写旧副本。
- 继续复用一份 `AgentQuestionPack` schema，不为 HTML 内嵌维护第二套批注格式；Markdown 只作为人工复制和受限浏览器兜底。
- 内嵌审核包使用非执行 `application/json` 节点和显式 marker，既方便 Agent 定位，也支持重复保存替换与发布版物理剥离。
- 含批注审核版和无批注发布版是两种明确产物：前者用于 Agent 回写，后者用于对外发送，默认文件名和按钮文案必须区分。
- 浏览器保存仍遵守本地文件安全模型：支持时弹系统保存选择，不支持时下载新文件；不承诺静默覆盖本地 HTML。
- 不引入后端、打包器或前端测试框架，保持离线单文件和零运行时依赖。

## 排除项及原因

- 不删除 Markdown 复制/下载：它仍是剪贴板受限、旧浏览器或人工审阅场景的兜底。
- 不把批注直接渲染成发布正文：结构化内嵌包更适合 Agent 定位和逐条处理，且发布版可完整剥离内部意见。
- 不自动采纳或删除用户批注：Agent 必须逐条处理，未采纳项需要说明原因；全部处理后才能移除内嵌审核区块。
