# v0.8.7

## 目标

把 `mgit` 从“用户点名时使用”的命令助手，调整为“模型根据多仓库任务上下文主动判断是否使用”的工具型 skill，同时保留高风险 MGIT 操作的确认门。

## 变更清单

- `mgit` 升级到 `0.1.3`
  - frontmatter description 改为上下文触发：多仓库工程、壳工程、跨子仓状态/分支/中间态/冲突/仓库范围判断都可触发
  - 明确用户没有说 `mgit` 时也可以主动使用只读 MGIT 诊断
  - 保留普通单仓 Git 不触发的边界
  - 明确写入、同步、推送、清理、reset 和跨仓自定义命令必须先确认影响范围
- README 更新 `mgit` 示例，把触发意图从“看一下 mgit 状态”改为“整体看一下这套工程状态”“这些改动在哪些仓”
- 插件版本升级到 `0.8.7`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- MGIT 是多仓工程的执行工具和安全护栏，不应仅作为用户手动点名的命令入口；模型应能根据任务是否跨仓来判断是否加载 skill。
- 只读诊断和高风险写操作分层处理：只读命令可主动使用，写入/同步/推送/清理/reset 等仍需确认，避免扩大影响范围。
- 触发描述保留“不适用于普通单仓 Git”，避免日常 commit、单仓 status 或 Git 概念问答误触发。

## 排除项及原因

- 不新增 MGIT 命令能力：本次只调整触发边界和安全说明，命令细节仍在 `references/` 中按需披露。
- 不放开自动推送或自动同步：这类操作影响多个仓库和远端状态，仍需用户确认。
