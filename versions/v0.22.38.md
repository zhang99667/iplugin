# v0.22.38 - 多业务透视表生成契约收敛

## 目标

让 `merge_pivots` 复用单透视表已有的字段兼容和输出安全机制，取代业务项目中的手拼多透视表包装脚本。

## 变更清单

- 多业务入口自动应用内置字段别名，并处理原始列与计算字段同名冲突
- 内置别名补充 `clk→click` 和 `asp_charge→charge`
- CLI 和 Python API 增加可选的明细 sheet 隐藏能力，默认行为保持不变
- 多业务输出改为同目录临时写入，OOXML 闸门逐个校验透视表、cacheId 和关系后再原子替换
- 增加多透视回归测试，覆盖别名/冲突、隐藏明细、失败不覆盖和第二个透视损坏检测

## 架构决策

- 字段标准化继续复用 `aliases.py` 和 `packager.py` 的现有逻辑，不在合并器内维护第二套规则
- `hide_data_sheets` 保持显式开关，避免改变现有调用方的默认工作簿布局
- 原子替换只在校验通过后发生，既有目标文件在生成或校验失败时保持不变

## 排除项及原因

- 不把特定项目的 sheet 名、实验号、对照组顺序或输出文件名写入 skill，这些继续由项目 JSON 配置管理
- 不改变 0 行业务的普通占位 sheet 策略，以避免重新引入空 pivot/cache 兼容问题
