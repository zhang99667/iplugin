# v0.13.5

## 目标

让 `mgit` skill 在执行 MGIT 命令前先处理 Ruby 启动依赖问题，避免 `colored2` 等 gem 缺失时反复直接运行 `mgit` 并中断。

## 变更清单

- `mgit` skill 升级到 `0.1.5`。
- 在最短执行流程中增加 MGIT 启动依赖预检：
  - `which mgit`
  - `ruby -v`
  - `ruby -e 'require "colored2"; require "peach"; require "tty-pager"; require "logger"; puts "mgit ruby deps ok"'`
- 缺少 `colored2`、`peach`、`tty-pager` 或 `logger` 时，要求先解释 Ruby gem path 问题并给出修复命令，不继续执行 MGIT。
- 依赖可加载但出现 `rbenv ... cannot create temp file` 时，明确这是执行环境限制，不是 MGIT 工作区问题。
- README 与两个 manifest 版本升级到 `0.13.5`，manifest 关键词补充 `ruby`、`gem`、`colored2`。
- EasyBox reference 补充输入解析和本地开源码规则：
  - 未给目标仓库时不默认开启广告仓库集合。
  - 完整 iCode 仓库名必须在 `xbuild/modules/default` 中按原始完整名查找，再反推 EasyBox 节点和层级。
  - 非目标模块已有 `syncSource true` 时默认保留。
  - 补充 `client`、`searchbox-lite`、`searchbox-tomas`、`hk-android-center` 等壳工程的默认主分支映射。

## 架构决策

- 不修改 MGIT 本身或用户的 Ruby 环境；skill 只负责在执行前发现问题并给出确定性修复路径。
- 不自动安装 gem。安装依赖会修改外部开发环境，必须由用户明确要求或批准。
- 预检命令保持轻量，只验证 MGIT 启动阶段已知硬依赖，不执行任何多仓库 Git 操作。
- EasyBox 开源码配置以当前壳工程 `xbuild/modules/default` 的实际命中为准，不维护静态仓库短名映射，避免产品线差异导致误开源码。

## 排除项及原因

- 不把 `bundle exec mgit` 作为默认路径：当前 MGIT 入口没有启用 bundler，且不同工作区可能没有完整 bundle 环境。
- 不把 rbenv 临时文件报错当作 gem 缺失处理：这是沙箱或终端权限问题，处理方式不同。
