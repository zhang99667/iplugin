# v0.21.9 - HTML 批注编辑与 SVG 自适应画布

## 目标

修复两个已有能力的可用性问题：

- html-report 离线批注审核模式中已有批注不能直接修改。用户在右侧栏发现批注内容写错时，应能原地编辑并提交，而不是删除后重新选择原文再添加。
- svg-tech-diagram 虽已有“按内容收缩”原则，但缺少硬性的内容包围盒计算流程，仍容易生成大留白 SVG。新规则要求按真实内容边界反推 `viewBox` 和背景尺寸。
- 多来源汇聚图容易把多条连线直接打到同一目标点，导致线条重叠或穿过节点。新规则要求先抽象汇聚层，并用几何和像素闸门拦截明显版面问题。

## 架构决策

- 复用现有 composer，而不是新增编辑弹窗。这样能保持离线批注模式轻量、单按钮提交和点击外侧关闭的原交互契约。
- 编辑只修改批注正文，不重选原文。批注定位、章节、选中文本和上下文属于原始证据，编辑时不应静默漂移。
- 在 `check_html_report.py` 中加入编辑能力闸门，避免未来修改注入脚本时把编辑入口删掉而校验仍通过。
- SVG 画布规则选择文档化强约束，不新增自动裁剪脚本。当前 SVG 多由模型手写坐标生成，最直接的失败点是缺少生成前后的计算口径。
- 视觉 QA 分三层：静态几何脚本拦确定性连线问题，PNG 像素脚本拦空白和留白问题，最终仍必须读取 PNG 做人工/模型视觉判断。脚本通过不等于视觉合格。
- 继续使用 patch 版本，因为这是已有 html-report 批注模式和 svg-tech-diagram 画布规则的可用性修复，没有新增 skill、command 或破坏性接口。

## 排除项及原因

- 不增加富文本编辑、评论线程或状态流转。当前模式定位是轻量离线审核，复杂协作会让单文件 HTML 过重。
- 不支持编辑原文选区。重定位需要重新选择文本，超出这次“修改批注内容”的核心问题。
- 不新增外部依赖或后端服务。批注模式继续保持单文件、离线可用。
- 不新增自动修改 SVG 的裁剪脚本。本次新增的脚本只做检查，不自动改坐标，避免误裁 marker、阴影或文字。
- 不声称脚本能完全判断“好不好看”。复杂视觉重叠、阅读顺序和文字压线仍必须渲染后看图。
