# v0.8.4

## 目标

收窄各 skill 的自动触发边界，减少轻量问答、单文件解释、普通总结或普通 Git 操作误触发重型 skill 的情况。

## 变更清单

- 所有 `skills/*/SKILL.md` 补充统一的“适用 / 不适用 / 需要确认”触发边界
- `code-reading` 升级到 `0.1.2`
  - 明确只服务深度代码导读、完整执行链路和代码链路报告
  - 将“这个方法在哪里调用”“这个方法是怎么被调到的”等局部问题列为不适用
- 其他 skill 升级 patch 版本：
  - `ask-user-question` `0.1.2`
  - `delegated-search` `0.1.1`
  - `html-report` `0.2.6`
  - `icafe-delivery-archive` `0.1.2`
  - `karpathy-guidelines` `0.1.1`
  - `lite-diff-marker` `0.1.1`
  - `mgit` `0.1.1`
  - `project-summary` `0.1.1`
  - `session-rename` `0.1.1`
  - `sql-exp-replace` `0.1.1`
- README 的 `code-reading` 触发示例改为更明确的完整执行链路表达
- 插件版本升级到 `0.8.4`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- 把触发边界放在每个 `SKILL.md` 正文前部，便于 skill 加载后立即约束行为；frontmatter `description` 同步保留最关键的适用和不适用条件。
- 不把所有 skill 都改成只能手动调用。大部分能力仍允许模型自动触发，但需要明确匹配核心 use case。
- 对写入型或高风险 skill 增加“需要确认”边界，例如 iCafe 归档、Lite 标记、MGIT 跨仓操作和会话命名配置。

## 排除项及原因

- 不新增 eval：本次是触发边界文案优化，先通过结构校验保证插件一致性；后续可针对 `code-reading` 单独增加触发回归测试。
- 不拆分 skill：本次只收窄触发范围，不改变现有能力目录结构。
- 不改动 command 入口：`/ask-user-question` 和 `/htmlreport` 的职责保持不变。
