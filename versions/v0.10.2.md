# v0.10.2 — Hook 配置双端拆分

## 目标

1. 修复 Claude Code 默认扫描 `hooks/hooks.json` 时不认识 Codex `${PLUGIN_ROOT}` 变量的问题
2. 避免继续赌 Claude Code 与 Codex 是否支持同一套 hook 变量名
3. 保留 v0.10.1 的 Codex telemetry 能力

## 变更清单

### 新增
- `hooks/codex-hooks.json` — Codex 专用 PostToolUse hook 配置，使用 `${PLUGIN_ROOT}`

### 修改
- `hooks/hooks.json`
  - 改为 Claude Code 默认扫描专用配置
  - 命令路径改用 `${CLAUDE_PLUGIN_ROOT}/hooks/skill-telemetry.py`
  - matcher 从 `*` 收窄为 `Skill`
- `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.10.2`
  - hooks 路径改为 `./hooks/codex-hooks.json`
- `.claude-plugin/plugin.json`
  - 插件版本升级到 `0.10.2`
- `scripts/validate-plugin.py`
  - 同时校验 `hooks/hooks.json` 和 Codex manifest 声明的 hooks 配置
- `README.md` / `CLAUDE.md` / `AGENTS.md`
  - 明确 Claude Code 使用 `${CLAUDE_PLUGIN_ROOT}`，Codex 使用 `${PLUGIN_ROOT}`

## 架构决策

**不采用单文件双端变量兼容**：`${CLAUDE_PLUGIN_ROOT}` 是否被 Codex 支持尚不确定，而 `${PLUGIN_ROOT}` 已被 Claude Code 展开为空造成实际路径错误。因此拆成 `hooks/hooks.json` 与 `hooks/codex-hooks.json` 两份薄配置，脚本仍然共用。

**Claude matcher 收窄为 `Skill`**：Claude Code 有明确的 `Skill` tool 事件，不需要监听所有 PostToolUse。Codex 当前没有完全等价的稳定事件形态，因此 Codex 侧继续使用 `*` 并由脚本过滤。

## 排除项

- 不把 Claude Code 的 hook 配置挪到 manifest：Claude Code 会默认扫描 `hooks/hooks.json`，保留默认路径最少惊扰。
- 不改变日志 schema：本次只修配置加载路径，避免把修 bug 扩大成 telemetry 数据结构迁移。
