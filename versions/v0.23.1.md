# v0.23.1 - DataPilot PRO 重试流程

## 目标

把 DataPilot SQL 任务的失败重试阈值和 PRO 引擎入口写成可执行的统一规则，避免重复使用容易失败的智能引擎，也避免页面操作时找不到 PRO 入口。

## 变更清单

- `skills/datapilot-sql-runner/SKILL.md`
  - skill 版本从 `0.1.3` 升级到 `0.1.4`
  - 同一逻辑 SQL、同一日期第二次出现明确 `FAILED` / `OVERTIME` 后，下一次重试切换 PRO 引擎
  - 明确从编辑器底部 `run` 右侧下拉箭头打开引擎菜单，选择 `PRO引擎` 后再提交
  - 补充 PRO 任务类型确认、`runs.jsonl` 记录要求和页面异常停止条件
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本从 `0.23.0` 升级到 `0.23.1`
- `CHANGELOG.md`
  - 记录本次 DataPilot 重试流程优化

## 架构决策

- 失败阈值按 `runs.jsonl` 的 `retry_of` 链统计，保证跨多次重试仍能识别同一 SQL、同一日期的失败次数。
- 只把明确的 `FAILED` / `OVERTIME` 计入阈值；HTTP 500、`UNKNOWN` 和暂时性接口异常继续跟踪原 task ID，避免误重提。
- PRO 入口保留在 Chrome 页面操作中，因为引擎下拉菜单属于 DataPilot UI 控件；提交后仍使用 task ID 和 MCP 能力跟进结果。

## 排除项及原因

- 不修改 DataPilot MCP 服务或 Chrome 插件实现：本次只补充 skill 调度规则和页面操作说明。
- 不自动重试未知状态任务：未知状态没有足够证据证明任务失败，自动重提会破坏任务追溯链路。
