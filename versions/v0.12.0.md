新增 `commercial-sql-writer` skill，把商业广告 SQL 写作沉淀为通用可复用能力：根据需求先判断表、字段、指标口径和场景模板，再输出可运行的 Hive/Spark SQL。

- 新增 `skills/commercial-sql-writer/references/scenario-router.md`，按大盘、实验、转化、半屏、优惠券、私信、下载、预渲染和排查场景路由。

## 架构决策

- 采用 progressive disclosure：`SKILL.md` 只保留触发、导航和核心流程，表结构、指标口径、SQL 模板和场景经验放入 `references/`。
- 不把本地外部目录路径写入 skill，避免能力绑定到个人机器目录；本次只沉淀可复用的业务规则和模板。
- 内部 KU 文档作为规则来源之一，但不把读取 KU 作为 skill 运行时硬依赖；可复用结论直接沉淀在 references 中。
- 将“最小改写已有大盘母版”放在“重新生成 SQL”之前，减少模型完全重写导致的口径漂移和转化逻辑丢失。
- 保持与 `sql-exp-replace` 的边界：纯实验号/日期替换仍由确定性替换 skill 处理，商业 SQL 写作才触发本 skill。
- 参考 Text-to-SQL 的 schema linking 思路：先选相关表字段，再写 SQL，避免把全量 schema 或大量历史 SQL 一次性塞入上下文。
- `html-report` 继续采用生成期静态预高亮，不引入 highlight.js、Prism、Shiki 等浏览器端高亮库，避免 CDN 或额外资源文件破坏单文件传输体验。
- 代码主题通过内嵌 CSS token 颜色实现，而不是引入外部 IDE theme 文件；这样可以接近 IDE 观感，同时不增加报告传输依赖。
- 将代码块验收沉淀为脚本，避免在 `SKILL.md`、内容规则和视觉规则之间重复维护同一组检查条件。

## 排除项及原因

- 不新增 slash command：当前场景更适合通过自然语言触发，避免命令入口过多。
- 不新增确定性脚本：SQL 生成需要业务判断，暂不适合脚本化。
- 不内置完整字段字典和所有历史 SQL：体量过大且容易过期，先沉淀高频规则和代表性模板。
- 不为 `html-report` 引入外部高亮依赖：继续复用现有标准库脚本，优先修正规则和验收不稳定的问题。
