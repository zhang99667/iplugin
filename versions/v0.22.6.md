# v0.22.6 - Obsidian 编辑工作流质量门禁

## 目标

把 `obsidian` skill 从写作建议和通用审校清单升级为可执行的编辑工作流，重点拦截参考风格失配、口播式标题、概念乱序、同义重复，以及用户只点名一处后未检查全文的问题。

## 变更清单

- `skills/obsidian/SKILL.md`
  - 保持尚未发布的 skill `0.3.0`，在现有模式路由、证据合同、配图和发布流程上增加硬门槛。
  - 将工作模式与文档类型分开；指定参考文时必须先完成 style profile，完整技术指南必须先完成 knowledge map。
  - 结构编辑轮和文风编辑轮覆盖标题、正文、表格、引用块、作者新增代码注释与 SVG 文字。
  - 用户反馈后保持必要最小编辑，但对同类缺陷执行全文和关联图示回归。
- `skills/obsidian/references/`
  - `content-brief.md` 增加 style profile 和 knowledge map 工件及进入正文的退出条件。
  - `writing-modes.md` 增加完整技术指南类型和默认概念依赖链。
  - `style-and-format.md` 增加专业标题规则和口播风险表达。
  - `quality-review.md` 将结构、文风审查设为强制轮次，并明确用户反馈后的全篇回归。
- `skills/obsidian/assets/templates/technical-chain.md`
  - 将连续问句标题改为直接命名入口、数据、分支和排查位置的名词性标题。

  - 单测覆盖有效/失效图片、远程图片、围栏与行内代码示例、ATX/Setext 一级标题、收尾结构、损坏 SVG 和伪 SVG XML。

- `README.md`、`.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 同步能力说明，插件版本升级到 `0.22.6`。

## 架构决策

- 保留证据收集、写作合同、配图 brief、图前说明/图后结论和 Obsidian Markdown 约束；本次增加的是编辑门禁，不推翻现有成熟流程。
- `SKILL.md` 只保留条件、顺序和退出门槛，详细工件与检查表放在一级 references，避免核心指令继续膨胀。
- 图片存在性和 SVG XML 交给确定性脚本；概念顺序、无证据事实、语义重复和图文术语冲突交给带 ground truth 的行为 eval，避免正则误判主观质量。
- 行为 eval 沿用仓库数据集模式，不绑定单一模型 runner。任务 Agent 只读取 prompt 与原始 fixtures，grader 再按原子 expectations 判定，防止预期答案泄漏。
- 编辑范围与审查范围分离：旧文仍优先局部修改，但用户指出系统性缺陷时必须扫描完整交付物。

## 排除项及原因

- 不禁止所有问句。只有概念定义或读者会自然提出的问题适合问句，风险表达需要结合上下文判断。
- 不用静态脚本判断 AI 味、概念依赖或 SVG 语义一致性；这些判断无法靠通用正则稳定完成。
- 不把完整技术指南强制绑定 `type: post`。私有 note 和公开文章都可以使用该内容类型，发布形态只决定元数据与读者测试门槛。
- 不新增 slash command。自然语言触发和现有 `obsidian` skill 足以承载该流程。
