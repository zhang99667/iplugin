# v0.4.2

## 目标

优化 `html-report` 的输出判断，避免所有 HTML 都被处理成普通对话页面。对于技术详设、代码评审、问题排查、需求交付、项目总结等更正式的文档，首屏需要有清晰抬头，方便读者快速识别文档类型、涉及仓库和上下文。

## 变更清单

- `html-report` 升级到 `0.2.4`
- 生成 HTML 前增加内容类型判断：正式技术/业务文档、分析报告、普通对话转 HTML
- 正式技术/业务文档和分析报告要求加入文档抬头
- 抬头字段覆盖文档类型、标题、仓库/模块、任务号、负责人、日期、状态等
- CSS 模板新增 `.doc-header`、`.doc-meta`、`.doc-chip` 样式和骨架示例
- 明确缺失或无法可靠判断的信息不能编造，拿不准时先问用户

## 架构决策

- 将“是否加正式抬头”放在生成 HTML 前的语义判断阶段，而不是固定套模板，避免普通对话转 HTML 被过度包装。
- 抬头字段只允许使用用户输入、当前上下文或本地可靠信息，缺失时宁可省略或询问，避免生成看似正式但事实不准确的元信息。
- 抬头样式放入 `css-template.md`，让后续报告复用同一结构，不在每次生成时临时拼接样式。

## 排除项及原因

- 不强制所有 HTML 加抬头；普通对话整理保持轻量页面即可。
- 不把文档类型做成固定枚举；实际使用中可能有技术详设、上线方案、复盘、评审报告等多种名称，保留模型按内容判断的空间。
- 不引入复杂封面页；报告首屏仍以可读、可扫的工程文档为主。
