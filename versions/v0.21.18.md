# v0.21.18 - HTML 报告语言清单单一真源

## 目标

解决 `html-report` 语言清单和代码块规则重复的问题。新增 Objective-C 时已经暴露出脚本支持、校验白名单和 reference 文档之间容易残留旧清单；本次把支持语言收敛到 `highlight_code.py` 一处。

## 变更清单

- `skills/html-report/scripts/highlight_code.py`
  - 新增 `--list-langs`，输出包含 `languages` 和 `aliases` 的 JSON 注册表。
  - 将 `--lang` 改为在非 `--list-langs` 模式下必填，便于单独查询语言清单。
- `skills/html-report/scripts/check_html_report.py`
  - 删除脚本内重复维护的 `SUPPORTED_LANGS`。
  - 启动时从同目录 `highlight_code.py` 加载 `SUPPORTED_LANGS`，让校验白名单复用高亮脚本的语言注册表。
- `skills/html-report/SKILL.md`、`references/content-rules.md`、`references/visual-rules.md`、`references/css-template.md`
  - 文档不再维护完整语言清单，改为要求使用 `python3 skills/html-report/scripts/highlight_code.py --list-langs` 查询当前支持语言和别名。
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.18`。

## 架构决策

- 选择 `highlight_code.py` 作为单一真源，因为它是真正执行语言规范化、别名映射和 diff 后缀推断的脚本。
- 暂不新增 `highlight_langs.json`。当前语言集合规模较小，直接暴露 `--list-langs` 可以避免额外配置文件和迁移成本。
- 校验脚本通过本地 import 读取 `SUPPORTED_LANGS`，不走子进程，避免每次校验 HTML 都额外启动一次高亮脚本。

## 排除项及原因

- 不在本次重构 tokenizer、关键字表或 Pygments 映射。单一真源先解决“清单漂移”，高亮质量优化可以独立处理。
- 不自动生成 README 或 manifest 关键词。对外描述没有新增语言能力，本次只是维护结构优化。
