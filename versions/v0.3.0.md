# v0.3.0 — 新增 Claude Code 会话自动命名 Skill

**日期**: 2026-05-20

## 目标

新增 `session-rename` skill，解决 Claude Code 会话没有标题导致后续难以检索的问题。Skill 沉淀自动命名方案：优先使用 `UserPromptSubmit` hook 返回 `sessionTitle`，在会话早期根据用户第一轮 prompt 生成短而可搜索的标题。

## 变更清单

- 新增 `skills/session-rename/SKILL.md`
  - 说明适用触发场景：重命名当前会话、自动给会话命名、以后方便找会话等。
  - 推荐使用 `UserPromptSubmit` hook 的 `sessionTitle` 输出实现自动化。
  - 提供本地 hook 脚本模板和 settings.json 配置示例。
  - 保留手动命名当前会话的备选流程。
- 更新 `CHANGELOG.md`，记录新增 skill。

## 架构决策

### 决策 1: 自动化由 hook 实现，而不是 skill 自触发

Claude Code skill 适合在用户表达意图后提供流程指导，但不适合在每次会话开始时自动运行。自动行为应由 settings 中的 hooks 承载，运行时稳定、可控，也符合 Claude Code 的配置模型。

### 决策 2: 使用官方 `sessionTitle`，不直接改内部 session 文件

调研确认 `UserPromptSubmit` hook 可以通过 stdout JSON 返回 `sessionTitle` 设置会话标题。该方式比修改 `~/.claude/sessions/*.json` 更安全，避免依赖内部存储结构和并发写入风险。

### 决策 3: hook 内使用本地启发式生成标题

不建议从 hook 中调用 Claude 或外部服务：hook 会阻塞用户 prompt 处理，调用模型可能慢、递归且不稳定。当前方案用本地规则生成 kebab-case 标题，保证快速和低风险。

## 排除项及原因

- 不直接修改 `~/.claude/settings.json`：本次是新增 skill，是否启用自动 hook 由用户单独确认或通过 update-config 流程执行。
- 不新增共享 `scripts/`：hook 脚本模板写在 skill 内，真正安装位置应在用户级 `~/.claude/hooks/`，不应绑定插件仓库路径。
- 不批量重命名历史会话：历史会话可能需要更复杂的人工确认，当前聚焦新会话自动命名和当前会话手动命名。
