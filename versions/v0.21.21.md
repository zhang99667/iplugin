# v0.21.21 - HTML 报告批注资产拆分

## 目标

修复 `html-report` 的 P2 维护性问题：`inject_annotation_mode.py` 单文件过大，批注模式 CSS、HTML 和 JS 全部塞在 Python 字符串里，后续调整 UI、路径字段或发布版剥离逻辑时风险较高。

## 变更清单

- `skills/html-report/assets/annotation-mode/`
  - 新增 `annotation.css`：维护批注审核模式样式，保留 `QA_ANNOTATION_CSS_START/END` 剥离标记。
  - 新增 `annotation.html`：维护右上角入口、选区气泡、右键菜单、输入浮层、侧栏和手动复制弹窗，保留 `QA_ANNOTATION_HTML_START/END` 剥离标记。
  - 新增 `annotation.js`：维护批注交互逻辑、Markdown/JSON 导出和发布版导出，保留 `QA_ANNOTATION_SCRIPT_START/END` 标记与 `__QA_REPORT_META__` 占位符。
- `skills/html-report/scripts/inject_annotation_mode.py`
  - 从内嵌大字符串改为读取 `assets/annotation-mode/` 三类资产。
  - 注入前校验 marker 和 `__QA_REPORT_META__`，缺失时给出明确错误。
  - 继续负责幂等清理、来源路径元数据注入和单文件 HTML 装配。
- `scripts/validate-plugin.py`
  - 新增批注资产完整性检查，提交前发现资产缺失、marker 丢失或 JS 占位符丢失。
- `skills/html-report/SKILL.md`、`references/annotation-mode.md`
  - 记录批注资产目录和维护约束。
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.21`；`html-report` skill 升级到 `0.3.14`。

## 架构决策

- 保持最终 HTML 单文件交付不变。资产拆分只影响源码维护方式，运行时仍由 `inject_annotation_mode.py` 内联 CSS、HTML 和 JS。
- 保留原有 marker 文本。这样现有 `check_html_report.py`、重复注入清理和浏览器端导出发布版逻辑都不需要改变语义。
- 不在本次拆分 JS 内部模块。当前收益最大的是把 Python 从长字符串载体改为装配器；JS 继续保持一个资产文件，避免一次重构引入行为变化。

## 排除项及原因

- 不改变批注 UI 行为。此次是维护性重构，所有交互、导出包字段和发布版剥离逻辑保持原样。
- 不引入构建步骤或打包器。`html-report` 仍强调零依赖、标准库脚本和离线单文件输出。
- 不把批注资产并入 `references/css/`。这些文件不属于普通报告样式组件，只服务注入脚本，放在 `assets/annotation-mode/` 更贴近用途。
