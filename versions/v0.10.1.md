# v0.10.1 — Codex Hook 兼容

## 目标

1. 让 v0.10.0 新增的 telemetry hook 同时支持 Codex 插件环境
2. 保留 Claude Code 既有日志路径和安装方式，不破坏已配置用户
3. 用版本记录修正 v0.10.0 中“Codex 端不做”的过时排除项

## 变更清单

### 新增
- `hooks/hooks.json` — Codex 插件默认 hook 配置，注册 `PostToolUse` command hook
- `.codex-plugin/plugin.json` — 显式声明 `"hooks": "./hooks/hooks.json"`

### 修改
- `hooks/skill-telemetry.py`
  - 保留 Claude Code `tool_input.skill` / `tool_name == "Skill"` 识别逻辑
  - 新增 Codex 事件兼容：从 `tool_input` 等工具输入参数中的 `skills/<name>/SKILL.md` 访问痕迹提取 skill 名称
  - Claude 默认写入 `~/.claude/skill-usage.jsonl`
  - Codex 默认写入 `~/.codex/skill-usage.jsonl`
  - 新增 `IPPLUGIN_SKILL_USAGE_LOG` 环境变量用于覆盖日志路径
- `README.md` — 补充 Codex 插件刷新、`/hooks` trust 和双端日志路径
- `CLAUDE.md` / `AGENTS.md` — 明确 hooks 已启用且双端配置要分别验证
- `scripts/validate-plugin.py` — 新增 Codex hooks 配置校验，检查 manifest hooks 路径和 hooks JSON 结构

## 架构决策

**Codex 使用插件内置 hooks/hooks.json**：Codex 官方支持插件根目录下的 `hooks/hooks.json`，manifest 也可显式声明 hooks 路径。本次两者都满足，便于未来迁移或排查。

**PostToolUse matcher 使用 `*`，脚本内过滤**：Codex 当前没有 Claude Code 完全等价的 `Skill` tool 事件保证。为了兼容 Bash、MCP 或未来 Skill 事件中的 skill 文件访问痕迹，hook 先接收支持的 PostToolUse 事件，再由脚本只检查工具输入并无输出快速过滤非 skill 事件，避免从搜索结果里误记 skill。

**日志路径按平台分开**：Claude Code 继续写 `~/.claude/skill-usage.jsonl`，Codex 写 `~/.codex/skill-usage.jsonl`，避免两端事件 schema 混在同一默认文件里。确实需要合并时，用 `IPPLUGIN_SKILL_USAGE_LOG` 指定同一路径。

## 排除项

- 不承诺 100% 捕获 Codex skill 选择：Codex 并不保证所有 skill 触发都会以独立 `Skill` tool 暴露给 PostToolUse。本次只记录 hook 事件中可确定识别的 skill 名称，避免靠 prompt 文本猜测。
- 不新增 Claude Code manifest hooks：现有 Claude Code 安装方式仍通过 `~/.claude/settings.json` 注册，避免改变已有用户的插件加载路径。
