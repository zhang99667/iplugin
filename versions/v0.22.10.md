# v0.22.10 - HTML 评论定位失效保护

## 目标

修复同一路径、同标题的 HTML 报告被重新生成后，浏览器继续恢复上一版 `localStorage` 评论，导致评论数据仍在但 `blockId` 已无法命中当前正文的问题。保证 `保存评论结果到 HTML` 不再产出评论存在却无法定位的交接文件。

## 变更清单

- `skills/html-report/assets/annotation-mode/annotation.js`
  - 初始化、点击定位和保存前统一校验评论的正文目标。
  - 原 `blockId` 失效时，依次使用完整块原文、选区上下文和选中文本查找候选，并且只接受章节约束下的唯一最深层命中。
  - 唯一命中时更新当前 `blockId`、章节 ID 和章节标题，并同步回本地草稿。
  - 无法唯一命中时保留评论内容，但卡片显示“原文已变化”警告；定位操作给出明确提示，保存动作在打开文件选择器前停止。
- `skills/html-report/assets/annotation-mode/annotation.css`

## 架构决策

- 保留“路径 + 标题”的本地草稿兼容键，不通过更换存储键隐藏旧评论，避免用户误以为批注丢失。
- 文本迁移只接受唯一命中；章节和 DOM 包含关系用于排除父级大容器与重复文本。无法确认时阻止保存，不做模糊猜测。
- `data-block-id` 仍是保存后定位的权威锚点；文本只用于报告重新生成后恢复失效锚点，不替代正常定位链路。
- 保存门禁放在文件选择器之前，避免用户完成保存交互后才发现产物无效。

## 排除项及原因

- 不自动删除无法定位的评论：评论内容仍有人工参考价值，删除权保留给用户。
- 不把旧评论强行绑定到相似段落：相似文本可能属于另一章节或另一版方案，错误定位比显式阻塞风险更高。
- 不改变 `AgentQuestionPack` schema：问题来自运行时锚点失效，现有包结构已能表达定位和原文上下文。
