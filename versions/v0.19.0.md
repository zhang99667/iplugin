# v0.19.0 — SVG 技术绘图 skill

## 目标

新增一个可复用的 SVG 技术绘图 skill，把技术长文和报告配图中的结构、自审流程和基础视觉底线固定下来，避免位图放大变糊、ASCII 错位、箭头穿文字和多张图风格不统一的问题。

## 变更清单

- 新增 `skills/svg-tech-diagram/SKILL.md`，定义触发边界、绘图流程、渲染自审和 HTML report 协作方式。
- 新增 `references/style-system.md`，沉淀朴素浅色优先的技术图规范、灰阶线框、少量强调色建议、字体字号、节点和可读性底线。
- 新增 `references/svg-patterns.md`，沉淀 SVG 画布骨架、节点、箭头、fork、垂直流程、分层架构、泳道、对比矩阵和状态机模式。
- 新增 `references/review-checklist.md`，沉淀 A/B/C 级自审清单和用户反馈到漏检项的映射。
- 新增 `scripts/render_svg.py`，调用本机 `rsvg-convert` 把 SVG 渲染为 PNG，服务交付前视觉检查。
- README、CHANGELOG、Claude/Codex manifest 同步加入 SVG 技术图生成能力。
- 插件版本升级到 `0.19.0`。

## 架构决策

- 先做独立绘图 skill，不把 HTML report 集成写死；当用户要完整报告时，由 `html-report` 负责报告结构和最终 HTML 校验，本 skill 只负责图的 SVG 内容和视觉自审。
- 默认使用白底/浅底、灰阶线框和少量强调色，不追求暗色科技感；颜色是辅助信息结构的工具，不是固定皮肤。
- 将长规则放入 references，主 `SKILL.md` 只保留触发、导航和核心流程，符合 progressive disclosure。
- 渲染脚本只做 SVG 到 PNG 的确定性桥接，不引入复杂绘图 DSL 或模板引擎。
- 视觉自审要求“渲染 PNG 后读取预览”，把返工成本前移到交付前。

## 排除项及原因

- 不新增 slash command：普通自然语言触发已经足够，新增 command 会和同名 skill 产生重复入口。
- 不加入自动布局引擎：当前目标是固化绘图纪律和常用模式，复杂自动布局容易过度设计且不利于人工检查。
- 不内置示例输出图片：仓库只沉淀可复用规则和脚本，示例图后续可以在真实使用中按需补充。
- 不修改 `html-report` skill：先完成独立绘图能力，后续再基于实际使用经验考虑更深协作。
