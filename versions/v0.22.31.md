# v0.22.31 - HTML Report 批注复制反馈与路径修复

## 目标

修复批注侧栏中“复制批注给 Agent”看起来点击无反应的问题，并保证移动或另存后的 `file://` 报告仍把当前文件作为 Agent 回写目标。

## 变更清单

- 零批注时复制主按钮使用 `aria-disabled` 和禁用样式表达不可用，但保留点击反馈，明确提示先添加问题或评论。
- 批注运行时优先复用页面已有 `.toast`，缺失时自行创建带稳定 `#toast`、状态角色和 `aria-live` 的提示节点。
- `file://` 页面优先使用当前 `location.pathname` 和去除 hash 的当前 URL 生成交接包。
- 生成期注入路径继续用于 HTTP 预览和旧 localStorage 草稿迁移，不再覆盖当前本地文件路径。
- 同步更新组件校验器、Node 运行时测试、批注契约和版本记录。
- `html-report` skill 从 `0.7.9` 升级到 `0.7.10`，插件从 `0.22.30` 升级到 `0.22.31`。

## 架构决策

- 不放开零批注复制动作，只把原生 `disabled` 改为可聚焦、可解释的 `aria-disabled` 状态，由既有复制入口统一拦截并提示原因。
- toast 由批注运行时自给自足，同时兼容装配器已经创建的通用 `.toast`，避免要求所有报告预置固定 DOM。
- 当前 `file://` 路径代表用户实际打开和希望 Agent 修改的文件，优先级高于生成期元数据；HTTP 预览仍依赖生成期绝对路径。

## 排除项及原因

- 不改变有批注时的 Clipboard API 和手动 textarea 兜底流程。
- 不恢复已处理轮次的旧批注；`AgentReviewReceipt` 到达后继续清理上一轮草稿。
- 不改变批注包 schema、轮次状态或发布版剥离规则。
