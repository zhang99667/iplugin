# v0.21.20 - HTML 报告回归集

## 目标

为 `html-report` 建立第一阶段 P0 质量护栏。此前主要依赖人工试用和 `check_html_report.py` 的结构校验，只能发现 HTML 结构、代码块和媒体资源问题，不能稳定覆盖“报告整体质量退化”的高频场景。

## 变更清单

- `skills/html-report/evals/evals.json`
  - 新增 6 个真实 prompt 回归用例：
    - 代码评审报告：Findings 优先、严重级别、文件定位、聚焦 diff、测试缺口。
    - 问题排查报告：现象、影响范围、根因、证据链、修复和验证结果。
    - 技术方案报告：方案概述、接口契约、改动总览、影响面、风险和验证。

    - 批注审核模式：普通 HTML 先校验，再注入批注模式，再校验审核版。

## 架构决策

- eval 先采用数据集形态，不内置模型 runner。这样可以被 skill-creator、手工评审或后续 CI runner 复用，不把回归集绑定到单一执行平台。
- 每个 eval 包含可检查 expectations，而不是只保存 prompt。这样后续无论用人工评审还是自动 grader，都有稳定判分依据。
- `validate-plugin.py` 只做只读结构和路径校验，不执行模型、不生成 HTML，避免提交前检查变慢或依赖外部服务。

## 排除项及原因

- 不新增自动评测 runner。当前首要缺口是回归样本缺失；runner 需要结合实际执行平台和成本另行设计。
- 不把所有 fixture 生成成最终 HTML。回归集的输入应尽量贴近真实用户材料，输出由被测 skill 生成。
- 不强制所有 skill 都有 evals.json。先为 `html-report` 补 P0 护栏，其他 skill 可按风险逐步补齐。
