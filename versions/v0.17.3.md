# v0.17.3 — 稳定 HTML 行内代码和 diff 展示

## 目标

提升 `html-report` 输出稳定性：让 Markdown 行内代码不再残留为原始反引号文本或丢失渲染，并让代码变更 diff 始终使用同一套清晰样式。

## 变更清单

- `html-report` skill 升级到 `0.2.19`。
- Markdown 行内代码固定渲染为 `<code>...</code>`，例如 `` `d` ``、`` `support_full_screen` ``。
- `check_html_report.py` 新增正文 raw backtick 检查，拒绝未渲染的 Markdown 行内代码。
- `check_html_report.py` 新增 token CSS 检查，拒绝只有 `tok-*` span 但缺少 `.tok-*` 样式的代码块。
- 真实 unified diff 统一使用 `highlight_code.py --lang diff --diff-view` 生成 `.diff-card.diff-viewer`。
- `check_html_report.py` 拒绝普通 `language-diff` 代码块和没有 `.diff-viewer` 的手写 `.diff-card`。
- `highlight_code.py` 的 diff viewer 标题改为中文“代码差异 / 统一 diff · old/new 行号”。
- 插件版本升级到 `0.17.3`。

## 架构决策

- 行内代码只允许用 `<code>` 表达，因为原始反引号是 Markdown 语法，不是最终 HTML 的稳定展示结构。
- builtin 高亮的 HTML span 和 CSS 需要成对出现；只检查 `tok-*` span 会漏掉“结构存在但视觉不高亮”的页面。
- diff 展示由脚本生成，而不是让模型每次手写表格。这样能固定 old/new 行号、整行红绿背景、左侧变更轨道和 hunk header。
- 校验脚本负责兜底拦截旧路径：`language-diff` 和手写 `.diff-card` 都会失败，避免后续报告样式回退。

## 排除项及原因

- 不引入第三方 diff 渲染库：单文件离线 HTML 仍是 `html-report` 的基本约束。
- 不把 Before / After 双栏也强制改成 diff viewer：结构变化较大的方案对比仍可使用现有普通代码块和变更说明。
- 不增加浏览器运行时 diff 解析：diff 在生成期静态渲染，减少预览环境差异。
