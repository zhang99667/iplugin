# v0.19.18 - Push 前版本防撞与提交边界规则

## 目标

减少多人同时改插件版本时的版本号撞车，并把“提交时只提交自己改动”的协作约束写入维护指南，避免暂存区里已有其他任务或用户改动时被误带进提交。

## 变更清单

- `scripts/pre_push_version_check.py`
  - 新增 Git pre-push 版本防撞检查脚本。
  - push 前执行 `git fetch --prune <remote>` 获取远端 tracking 分支状态。
  - 若本地提交未包含远端最新提交，则拒绝 push，要求先 `git pull --rebase` 或 `git pull --ff-only`。
  - 若本地 manifest 版本不大于远端 manifest 版本，或远端已存在同版本 `CHANGELOG` / `versions` 记录，则拒绝 push。
  - 脚本注释使用中文，方法和关键分支内说明都解释检查意图。
- `git-hooks/pre-push`
  - 新增可版本化的 Git hook 入口，转发到版本检查脚本。
- `README.md`
  - 补充 `git config core.hooksPath git-hooks` 启用方式和手动检查命令。
- `CLAUDE.md` / `AGENTS.md`
  - 补充 `git-hooks/` 目录约定和 push 前版本防撞检查。
  - 补充提交边界规则：只能暂存并提交本次任务中自己产生的改动；同一文件混有其他修改时必须按 hunk 暂存，不能整文件带上。
- `scripts/validate-plugin.py`
  - 将 `git-hooks/` 纳入 README 顶层目录结构检查。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.19.18`。
- `CHANGELOG.md`
  - 新增 `0.19.18` 变更记录。

## 架构决策

- pre-push 阶段只 `fetch`，不在 hook 中自动 merge、rebase 或修改工作树。自动 pull 可能在 push 时改动当前分支或工作区，失败状态也更难恢复；fetch 后检测本地是否包含远端最新提交，可以达到“push 前先同步远端状态并拦截冲突”的目的。
- 版本冲突以 manifest 版本为主，并额外检查远端同版本 `CHANGELOG` 与 `versions` 记录，覆盖“版本文档先被别人占用但 manifest 尚未更新”的异常状态。
- Git hook 放在 `git-hooks/`，不混用现有 `hooks/`。现有 `hooks/` 已用于 Claude / Codex telemetry，保持边界清晰。
- “只提交自己的改动”不做 commit hook 强拦截。hook 无法可靠判断同一文件中每个 hunk 的来源，规则应要求提交前显式检查 `git diff --cached` 并用 `git add -p` 或明确路径控制暂存范围。

## 排除项及原因

- 不自动安装或强制修改 `.git/config`：Git hooksPath 是本地仓库配置，应由维护者显式执行一次 `git config core.hooksPath git-hooks`。
- 不支持自动分配下一个版本号：多人并发时自动递增仍可能产生二次竞争，脚本只负责在 push 前拦截风险。
- 不把完整插件结构校验塞进 pre-push：结构一致性仍由 `python3 scripts/validate-plugin.py` 负责，pre-push 只做远端相关的版本防撞。
- 不做 commit hook 拦截“非自己改动”：Git hook 没有可靠信号判断 hunk 归属，强拦截容易误伤正常提交或漏掉同文件混合修改。
