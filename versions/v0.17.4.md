# v0.17.4 — diff viewer 代码列语法高亮

## 目标

优化 `html-report` 的真实 unified diff 展示：在保留新增/删除红绿背景、old/new 行号和左侧变更轨道的基础上，让代码列也能显示语法高亮。

## 变更清单

- `html-report` skill 升级到 `0.2.20`。
- `highlight_code.py --lang diff --diff-view` 新增文件路径语言推断：根据 `---` / `+++` 行里的后缀识别 `java`、`kt`、`py`、`xml`、`json` 等已支持语言。
- diff viewer 的代码列复用现有 `highlight()` / `tok-*` 静态高亮逻辑，不新增第二套 tokenizer。
- CSS 模板补充 `.diff-viewer .tok-*` 浅色背景专用配色。
- `check_html_report.py` 新增 diff viewer token CSS 检查，避免代码列生成了 token 但缺少样式。
- `visual-rules.md` 与 `css-template.md` 同步说明 diff viewer 会给代码列生成语法高亮。
- 插件版本升级到 `0.17.4`。

## 架构决策

- 继续在生成期完成静态渲染，不引入浏览器端高亮库或运行时 diff 解析，保持单文件离线 HTML 输出。
- 复用现有 `highlight()` 高亮函数，避免普通代码块和 diff 代码列产生两套语法规则。
- 语言推断只基于 diff 文件路径后缀；无法识别时降级为安全转义文本，不阻塞报告生成。
- 删除文件场景保留 `--- a/file.ext` 推断出的语言；`+++ /dev/null` 不覆盖为纯文本。

## 排除项及原因

- 不在 diff viewer 中启用 Pygments：当前 `--engine auto/pygments` 只服务普通代码块，diff viewer 需要逐行渲染并保留行级新增/删除结构。
- 不实现跨行语法状态：多行字符串或块注释在 diff 单行渲染中可能不完整，但能覆盖关键字、字符串、数字、函数名、类型名等主要可读性需求。
- 不新增独立 diff 渲染库：现有标准库脚本已经能稳定解析 unified diff 的 hunk 和行号。
