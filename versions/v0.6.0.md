# v0.6.0

## 目标

新增一个 `karpathy-guidelines` skill，把上游 Karpathy 风格 LLM 编码准则翻译并引入到个人插件中。用户在写代码、重构、修 Bug 或 code review 时，可以要求助手按更谨慎的工程准则执行，减少过度设计、无关改动和缺少验证的问题。

## 变更清单

- 新增 `karpathy-guidelines` skill，版本 `0.1.0`
- 基于上游 `karpathy-guidelines/SKILL.md` 做中文翻译引入
- 保留本仓库要求的 `version`、`tags`、`user_invocable` frontmatter 字段
- 保留上游 MIT license 和 source 地址
- 覆盖四类执行约束：编码前先思考、简单优先、外科手术式改动、目标驱动执行
- 插件版本升级到 `0.6.0`，同步更新 Claude Code 与 Codex manifest 的描述、关键词和默认提示

## 架构决策

- 将该能力作为独立 skill，而不是写进全局维护指南，避免所有任务都被过度约束；只有编码、重构、review 等场景触发。
- 内容采用上游 `SKILL.md` 的中文翻译，避免本地二次扩写导致语义漂移。
- 保留 `karpathy-guidelines` 英文名称以匹配外部常见触发词。
- 不引入脚本或自动检查工具。这个 skill 主要约束执行行为和输出结构，验证仍依赖具体项目已有测试、构建和 lint 命令。

## 排除项及原因

- 不加入强制 hooks 或 pre-commit 检查；该能力是行为准则，不应改变用户仓库的提交链路。
- 不默认要求每个小任务都先长篇计划；简单任务可压缩表达，避免降低执行效率。
- 不把它做成通用写作或项目总结 skill；适用范围限定在编码、review 和工程改动。
