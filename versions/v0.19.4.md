# v0.19.4 - HTML 报告长文件链接展示优化

## 目标

优化 `html-report` 生成代码评审、问题排查报告时的文件定位 chip 展示。遇到特别长的源码路径时，正文仍要能快速看出仓库、模块、文件和行号，同时不牺牲 IDE 跳转能力。

## 变更清单

- `skills/html-report/SKILL.md`
  - 将 skill 版本升级到 `0.3.2`。
  - 在主规则中说明超长文件定位链接允许用 `...` 省略中间目录。
- `skills/html-report/references/visual-rules.md`
  - 补充长路径展示策略：省略只发生在中间目录，保留仓库/模块线索、文件名和行号。
  - 明确完整路径和完整定位必须保留在 `href` 与 `title` 中。
- `skills/html-report/references/css-template.md`
  - 路径 chip 增加 `max-width`、`box-sizing` 和 `overflow-wrap:anywhere`。
  - 示例改为短展示文本 + 完整 `title` / `href`。
- `skills/html-report/references/content-rules.md`
  - 完成前检查增加超长路径省略展示确认项。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.19.4`。

## 架构决策

- 只调整生成规则和 CSS 模板，不新增脚本或运行时 JS。路径是否过长属于生成期排版判断，直接在 HTML 展示文本中处理更稳定。
- `...` 只作为视觉展示，不作为真实路径的一部分；真实跳转仍依赖完整 `idea://open` 链接。
- 完整定位放在 `title`，方便鼠标悬停查看和复制核对。

## 排除项及原因

- 不强制固定截断长度：不同报告版宽、路径层级和同名文件冲突不同，固定字符数容易隐藏关键信息。
- 不只依赖 CSS `text-overflow: ellipsis`：它会隐藏文件名或行号，且难以表达“保留仓库和文件语义”的要求。
- 不在校验脚本中强制检查 `...`：并非所有路径都需要省略，规则应由生成报告时按可读性判断。
