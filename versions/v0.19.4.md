# v0.19.4 - DataPilot 运行中心跳检查

## 目标

补强 `datapilot-sql-runner` 在 SQL 已提交、任务仍处于排队或运行状态时的跟进方式。避免只回收任务 ID 后就结束，也避免无限等待。

## 变更清单

- `skills/datapilot-sql-runner/SKILL.md`
  - skill 版本升级到 `0.1.1`。
  - 输入收集补充是否需要心跳检查。
  - Chrome 提交流程在回收任务 ID 后增加心跳检查判断。
  - 新增“心跳检查”章节：默认 3 分钟一次，终态停止，无明确长等时最多 10 次或 30 分钟。
- `README.md`
  - DataPilot SQL 跑数能力说明补充运行中心跳检查。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.19.4`。
- `CHANGELOG.md`
  - 记录本次指令优化。

## 架构决策

- 保留 Chrome/Monaco 作为当前主路径，不引入未稳定上线的 DataPilot MCP 流程。
- 心跳只在任务已成功提交并拿到任务 ID 后生效，仍以 DataPilot 页面任务卡片状态为准。
- 默认间隔设为 3 分钟，兼顾 DataPilot 中等任务排队时间和对话噪音。
- 设置 10 次或 30 分钟上限，防止 Agent 在没有明确要求时无限等待。

## 排除项及原因

- 不新增脚本：心跳依赖 Chrome 页面状态和当前任务 ID，写在 skill 流程里更直接。
- 不默认等待所有任务完成：批量任务可能排队较久，默认仍先交付任务 ID 和当前状态。
- 不恢复 DataPilot MCP 主路径：当前 MCP 认证链路未稳定，继续以 Chrome 方式跑数。
