# v0.8.6

## 目标

把 `sql-exp-replace` 从“模型按规则手工改 SQL”升级为“模型确认参数，脚本执行确定性替换”的流程，降低漏替、误替和格式漂移风险。

## 变更清单

- 新增 `scripts/text_replace.py`
  - 作为通用替换引擎，支持 literal / token / regex 三类明确替换计划
  - 支持 token 后缀保留、替换计数、`expect_min` 和 0 命中失败
  - 连续 token 规则会按同一轮原文匹配同时替换，避免交叉映射串联污染
  - token 边界把连字符纳入保护，避免 `123-x` 被基础 token 误替换
  - 支持 JSON plan 或命令行参数，便于后续其他领域脚本复用
- 新增 `scripts/sql_exp_replace.py`
  - 作为 SQL 领域 wrapper，复用 `scripts/text_replace.py` 做机械替换
  - 支持 `--scan` 扫描候选实验号、独立数字 token 和 `FIELD between ... and ...` 日期条件
  - 支持 `--map OLD=NEW` 多组实验号映射
  - 基础实验号映射会保留 `-0` / `-dz` 后缀
  - 支持通过 `--date-field FIELD` 指定一个或多个日期字段，不再把字段固定死在 `event_day`
  - 基础日期字段名可匹配带表别名字段，例如 `event_day` 匹配 `a.event_day`
  - 支持替换指定字段的 `FIELD between YYYYMMDD and YYYYMMDD` 日期范围
  - 支持 `MMDD` + 四位 `--year` 的日期补全年份
  - 默认在映射或任一指定日期字段 0 命中时失败，防止静默漏替
  - stderr 输出替换计数，stdout 输出替换后的 SQL
- `sql-exp-replace` 升级到 `0.2.0`
  - frontmatter description 标明脚本优先
  - 新增先扫描、再由模型判断字段和映射、最后脚本替换的混合流程
  - 强调字段名不固定，日期字段和实验字段需要结合 SQL 语义确认
  - 保留原有触发边界和替换规则
- README 的 `sql-exp-replace` 用途说明更新为确定性脚本替换
- 插件版本升级到 `0.8.6`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- 通用替换能力下沉到 `scripts/text_replace.py`，避免每个领域脚本重复实现计数、0 命中失败和 token 边界替换。
- token 替换采用批量同时替换语义，优先保证实验号互换、重叠目标值等场景不会被上一条替换结果影响。
- SQL 领域判断保留在 `scripts/sql_exp_replace.py` 和模型流程中：实验号、日期这类规则明确的批量替换交给脚本，模型负责理解用户意图、确认字段语义、不明确映射和检查替换计数。
- 脚本提供 `--scan` 帮助模型发现候选项，但不自动决定哪些字段该改；字段名不固定时由模型结合 SQL 上下文传入 `--date-field`。
- 脚本只覆盖确定格式：实验号 token 和指定字段的 `between ... and ...`。复杂 CASE 标签、业务文案或不明确映射仍由模型判断或向用户确认。
- 默认 0 命中即失败，避免用户以为已完成但实际没有替换；需要容忍 0 命中时显式传 `--allow-zero`。
- 脚本只依赖 Python 标准库，保持插件在本地环境可直接运行。

## 排除项及原因

- 不引入 SQL parser：当前需求是保留原 SQL 格式做局部替换，扫描+确认+正则替换覆盖目标格式更轻量，也更少改变排版。
- 不自动推断年份：用户给 `0508` 这类 MMDD 时，必须由模型根据上下文明确年份后传 `--year`。
- 不自动修改所有日期字段或 CASE 标签：字段语义、标签语义和实验号映射不总是一一对应，保留给模型检查并在不明确时询问用户。
