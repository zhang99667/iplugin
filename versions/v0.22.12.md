# v0.22.12 - HTML 报告内容编排松绑

## 目标

减少 `html-report` 对章节名称、顺序和页面结构的过度约束，让模型根据读者任务和材料本身设计清晰主线，同时继续保证技术报告应有的内容、证据和代码变更表达不缺失。

## 变更清单

- 将 `artifact-patterns.md` 从七类“结构模板”改为内容覆盖清单，去掉暗示固定顺序的编号。
- 在 `content-rules.md` 增加简短编排流程：先判断读者任务，选择叙事主线并拟提纲，最后对照清单补缺和装配 HTML 组件。
- 转换已有文档时优先保留已经清晰的宏观顺序、概念依赖和教学提示，避免统一改写成通用正式报告。
- 区分首屏入口：结论型报告使用摘要，教程和前序知识可使用阅读地图、核心问题或学习目标。
- 技术方案与调研继续覆盖契约、流程、实现证据、影响面、风险和验证；存在真实代码或配置改动时仍要求文件定位与聚焦 diff。
- 新增知识手册结构保真 eval，并放宽技术方案 eval 对固定章节名的依赖。
- `html-report` skill 升级到 `0.5.2`，两个插件 manifest 同步升级到 `0.22.12`。

## 架构决策

- 只放开内容组织，不修改离线单文件、代码转义、高亮、diff viewer、响应式、打印、媒体和评论模式等确定性约束。
- 类型清单负责“不能漏什么”，模型负责“怎样讲最清楚”；内容完整性与结构自由度分层处理。
- 不新增另一套编排 reference，直接把少量核心规则放进现有 `content-rules.md`，避免为解决模板复杂度再引入新的流程复杂度。

## 排除项及原因

- 不修改 `check_html_report.py` 和 CSS 组件；本轮反馈集中在文章内容组织，不扩大到视觉系统重构。
- 不要求所有技术材料都出现 diff；只有真实代码或配置发生变化时才要求聚焦 diff，原理讲解和调研使用必要代码片段即可。
- 不把用户提供的具体业务文档收入 fixture；回归用例使用去业务化的最小知识手册提纲，只验证可复用行为。
