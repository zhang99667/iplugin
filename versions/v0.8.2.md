# v0.8.2

## 目标

优化 `code-reading` skill 的触发边界和输出结构，让它只在用户明确需要深度代码导读、完整执行链路或 HTML 报告时触发，避免普通代码问答被过度升级。

## 变更清单

- `code-reading` 升级到 `0.1.1`
- 收紧 frontmatter description 的触发短语，明确轻量代码问答不应触发该 skill
- 新增触发边界章节，区分“应该触发”和“不应该触发”的用户表达
- 强化执行链路拆解结构，覆盖数据来源、对象创建、初始化绑定、触发入口、动态分发、状态变化和副作用
- 补充 HTML 报告要求，强调报告正文按真实代码执行顺序组织，并使用图示表达复杂链路
- 插件版本升级到 `0.8.2`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- 将 `code-reading` 定位为深度导读 skill，而不是所有代码解释任务的默认入口，减少误触发和输出过重的问题。
- 输出结构从“创建、初始化、事件注册、触发、分发”扩展为更完整的执行叙事链路，适配 View、队列、Runnable、Animator、回调和状态机等复杂场景。
- 对 HTML 报告仍复用 `html-report` skill，不在 `code-reading` 中复制完整 HTML 生成规范，只补充代码链路报告的组织要求。

## 排除项及原因

- 不新增独立脚本：本次是 skill 指令优化，不涉及确定性代码生成。
- 不改动 `html-report` 触发边界：本次只约束 `code-reading` 如何调用和组织报告内容。
- 不删除轻量代码问答能力：轻量问答仍由普通代码分析流程直接完成，只是不再触发深度导读 skill。
