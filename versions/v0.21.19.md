# v0.21.19 - HTML 报告类型模板补齐

## 目标

补齐 `html-report` 的高频报告类型模板。此前 `artifact-patterns.md` 主要覆盖技术方案、技术调研和问题排查/修复方案，代码评审、验收、选型对比、项目总结仍依赖通用规则，输出结构不够稳定。

## 变更清单

- `skills/html-report/references/artifact-patterns.md`
  - 新增代码评审报告模板，强调 Findings 优先、严重级别、文件定位、聚焦 diff、测试缺口和残余风险。
  - 新增验收报告模板，强调验收范围、环境、case 矩阵、逐 case 证据、缺陷风险和原始证据。
  - 新增选型对比报告模板，强调决策问题、候选方案、评价标准、对比矩阵、推荐和验证计划。
  - 新增项目总结报告模板，强调目标、交付范围、时间线、结果证据、关键取舍、经验和后续行动。
  - 更新选择规则和降级规则，避免高频报告继续误套通用结构或技术调研结构。
- `skills/html-report/SKILL.md`
  - 将 `html-report` skill 版本升级到 `0.3.12`。
  - 更新 progressive disclosure 说明和最短执行流程，声明七类高频模板。
- `README.md`
  - 同步 `html-report` 的报告类型模板能力说明。
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.19`。

## 架构决策

- 继续把报告类型模板放在 `references/artifact-patterns.md`，让 `SKILL.md` 只保留触发、路由和输出契约。
- 模板只描述结构、证据要求和 HTML 表现建议，不内嵌完整 HTML 示例，避免 reference 文件再次变成大模板文件。
- 代码评审和验收报告优先补足证据结构，因为这两类最容易因章节顺序不稳定导致实际交付质量退化。

## 排除项及原因

- 不新增独立 report-template skill。报告结构仍属于 `html-report` 的领域能力，拆成新 skill 会增加触发和维护成本。
- 不新增生成器脚本。当前问题是报告组织规则缺失，先通过 reference 模板稳定输出；生成器需要等回归集建立后再评估。
- 不新增 eval/fixture。回归集属于下一阶段 P0 质量护栏，本次只补模板能力面。
