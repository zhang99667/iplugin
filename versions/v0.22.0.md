# v0.22.0 - xbuild 源码模式打开助手

## 目标

把“根据崩溃栈/类名/仓库名判断要开哪个 EasyBox/xbuild 源码仓，并修改 local/overlay 覆盖文件”的经验沉淀成可复用 skill。目标是减少每次手工搜索 `xbuild/modules/default`、判断 `syncSource true` 层级和区分业务仓/SDK 仓的重复成本。

  - 触发场景覆盖“开源码”“打开仓库”“打开模块源码模式”“加到 modules-local/modules-overlay”“syncSource true”以及从崩溃栈、类名、包名、模块名、远端仓库反查 xbuild 模块。

## 架构决策

- 不把开源码逻辑合并进 `mgit`。`mgit` 继续负责多仓状态、同步、分支和中间态诊断；`xbuild-open-source` 专注 xbuild 模块映射和 local/overlay 配置修改。两者协作但边界清楚。
- 长规则放入 `references/xbuild-source-mode.md`，`SKILL.md` 只保留触发、流程和安全边界，遵循 progressive disclosure。
- 不提供自动 `mgit sync` 脚本。打开 `syncSource true` 是配置修改；拉仓、切分支、清理等跨仓写操作必须由执行 agent 明确说明影响范围并取得确认。

## 排除项及原因

- 不新增 slash command。该能力更适合自然语言触发，且 iPlugin 目前已将常见命令入口收敛到 skill 触发语义。
- 不修改 `xbuild/modules/default`。该 skill 的目标是使用 default 作为映射真源，在 local/overlay 中做个人或分支覆盖。
- 不自动推断所有广告常用仓并批量打开。不同壳工程和分支场景差异较大，必须以当前 default 配置和用户目标为准。
