## 架构决策

- 继续使用 `highlight_code.py` 的零依赖 builtin 引擎做基础高亮，避免为了新增语言把 HTML 报告生成流程绑定到外部依赖或联网安装。
- Objective-C 统一规范化为 `objc`，并把 `objective-c`、`obj-c`、`.m`、`.mm`、`.h` 映射过去，让命令行和 diff 后缀推断都能复用同一套语言名。
- TypeScript 从旧的 `js` 别名提升为独立 `ts`，保留 JavaScript 高亮逻辑的同时补充 `interface`、`type`、`keyof` 等 TypeScript 关键字。
- Markdown 只高亮标题、引用、列表标记和行内代码，不尝试完整解析 Markdown。这样可以保护 HTML 转义边界，并保持脚本无依赖。

## 排除项及原因

- 不引入 highlight.js、Prism、Shiki 或 Pygments 依赖安装。`--engine auto` 仍只探测本机已有 Pygments，默认路径保持确定性和离线可用。
- 不追求完整编译器级语法解析。报告里的高亮目标是提升阅读定位，不应该因为复杂语法覆盖增加维护成本和误判风险。
- 不为每种语言单独增加 CSS。现有 `tok-*` 语义 class 足够表达关键字、字符串、数字、注释、函数、变量和类型。
