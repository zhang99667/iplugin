# v0.22.2 - DataPilot MCP 优先跑数

## 目标

把 `datapilot-sql-runner` 的默认执行路径从 Chrome/Monaco 页面操作调整为 DataPilot MCP 优先，减少页面编辑器、多标签隐藏 textarea 和登录态插件连接带来的不稳定性。

## 变更清单

- `skills/datapilot-sql-runner/SKILL.md`
  - skill 版本升级到 `0.1.2`。
  - frontmatter 描述和 tags 补充 MCP 优先语义。
  - 新增“执行路径选择”和“MCP 跑数主路径”，要求先发现 DataPilot MCP，再用 `datapilot_submit_sql`、`datapilot_get_sql_result`、`datapilot_sql_download_judge`、`datapilot_sql_download` 等工具提交和跟进。
  - Chrome/Monaco 页面操作改为回退路径，仅在 MCP 不可用、认证失败、能力不覆盖或用户明确要求浏览器操作时使用。
  - 增加重复提交保护：MCP 已返回 `task_id` 后，后续查询失败也不能自动改用 Chrome 再提交同一 SQL。
- `README.md`
  - 更新 `datapilot-sql-runner` 能力说明，突出 MCP 提交、查状态和下载结果的优先级。
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本升级到 `0.22.2`。
  - keywords 补充 `mcp`。
- `CHANGELOG.md`
  - 记录本次指令优化。

## 架构决策

- 不新增独立 DataPilot MCP skill。用户目标仍然是“跑 SQL 并回收任务 ID/结果”，MCP 只是更稳定的执行通道，放在同一个 skill 内能保持触发入口一致。
- 保留 Chrome/Monaco 经验作为回退路径。DataPilot MCP 可能遇到认证、权限、任务类型或页面专属控件覆盖不足的问题，已有页面操作经验仍然是必要兜底。
- 对 `task_id` 做唯一锚点。只要 MCP 返回任务 ID，就认为任务已经提交，后续失败应围绕该任务查询，不应为了确认状态重复提交 SQL。

## 排除项及原因

- 不改 DataPilot MCP 工具实现：本次只更新 skill 调度规则，不触碰外部 MCP 服务。
- 不移除 Chrome 相关说明：页面流程仍用于 MCP 不可用或用户指定页面设置的场景。
- 不新增 command：自然语言触发已经足够，新增 slash command 会造成同名能力重复维护。
