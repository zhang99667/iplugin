# v0.22.24 - HTML Report 稳定批注入口

## 目标

把评论版右上角固定为可预测的批注入口，并让“完成批注”明确承担批注写回 HTML 的交接职责，避免零批注时入口突然变成发布版导出。

## 变更清单

- 右上角入口固定显示“批注”，有批注时通过独立数量徽标表达当前条数，零条时隐藏徽标。
- 点击右上角入口始终打开或关闭批注侧栏；“导出无批注版”只保留在侧栏。
- 侧栏主操作从“保存评论结果到 HTML”改为“完成批注”，成功反馈明确提示批注已写入 HTML，可将文件交给 Agent。
- 校验器拒绝入口职责切换、`publish-mode` 和零条直接导出逻辑，并补充组件回归与 eval 契约。
- `html-report` skill 从 `0.7.3` 升级到 `0.7.4`，插件从 `0.22.23` 升级到 `0.22.24`。

## 架构决策

- 批注工作区和对外发布是两个独立任务：固定入口只负责进入工作区，发布动作留在侧栏的明确按钮中。
- 数量仅表示当前工作状态，不决定按钮行为；合法的零批注包仍可通过“完成批注”写回 HTML。
- 继续复用既有 `saveReviewHtml`、`AgentQuestionPack` 和发布版物理剥离逻辑，不修改数据 schema 或 Agent 回写流程。

## 排除项及原因

- 本批不加入 Agent 回复、已解决状态、diff 审阅或阶段检查点，避免同时扩大交互和数据契约的影响面。
- 本批不调整批注卡片、选区气泡和右键菜单，其现有行为与稳定入口无直接冲突。
- 本批不改变发布版文件结构；现有 UI、脚本、内嵌包、高亮、定位 ID 和本地路径剥离规则继续生效。
