# v0.21.2 - generate-image 通用图片生成

## 目标

把图片生成能力从 `comate-image` 重命名为 `generate-image`，避免 skill 身份和某个具体网关绑定。Comate 兼容接口只作为可指定后端和旧环境变量兼容项存在，不再出现在能力名称、插件主描述或默认提示里。

## 变更清单

- `skills/generate-image/SKILL.md`
  - skill 从 `comate-image` 重命名为 `generate-image`。
  - skill 版本升级到 `0.1.2`。
  - 目标改为通用图片生成流程：普通出图可使用平台内置图像能力；需要本地保存、指定接口或可复现 CLI 时使用内置客户端。
  - API key 主变量改为 `GENERATE_IMAGE_API_KEY` / `GENERATE_IMAGE_API_KEY_FILE`，旧 `COMATE_*` 变量只做兼容读取。
- `skills/generate-image/scripts/generate_image_client.py`
  - 脚本从 `comate_image_client.py` 改名为 `generate_image_client.py`。
  - 对外错误名改为 `generate_image_error`，默认输出 fallback 改为 `generate-image`。
  - 支持 `GENERATE_IMAGE_BASE_URL` 覆盖默认网关。
- `skills/generate-image/references/generate-image-apis.md`
  - 参考文档从 Comate 专属接口摘要改为 provider-compatible 图片网关摘要。
- `README.md`
  - Skills 表新增 `generate-image`，移除当前能力入口中的 `comate-image`。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.2`。
  - 插件描述、关键词和 Codex 默认提示改为通用图片生成入口。
- `CHANGELOG.md`
  - 新增 `0.21.2` 版本记录。

## 架构决策

- 不保留 `comate-image` alias skill。skill 目录名必须和 `SKILL.md` 中的 `name` 字段一致，继续保留旧 skill 会造成两个入口重复维护，并把旧命名继续暴露给用户。
- 保留旧 `COMATE_API_KEY` / `COMATE_API_KEY_FILE` 读取兼容，避免用户已有本地环境立刻失效；新文档和询问流程只引导设置 `GENERATE_IMAGE_*`。
- 默认 base URL 仍由客户端提供，但支持 `GENERATE_IMAGE_BASE_URL` 覆盖，后续切换网关不需要再重命名 skill。

## 排除项及原因

- 不改写历史版本记录里的 `comate-image`：那些文档记录的是当时的实际命名，改写历史会降低版本决策可追溯性。
- 不新增 slash command：自然语言触发已经足够，重复 command 会带来额外维护成本。
