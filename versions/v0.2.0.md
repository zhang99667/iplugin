# v0.2.0 — 新增 MGIT 多仓库管理 Skill

**日期**: 2026-05-19

## 目标

新增 `mgit` skill，把百度 MGIT 多仓库管理工具的高频使用方式沉淀为可复用的 Claude Code 操作指南，降低多仓库状态诊断、同步、分支切换、批量提交/推送和中间态处理的误操作风险。

## 变更清单

- 新增 `skills/mgit/SKILL.md`
  - 覆盖 MGIT 工作区识别、只读诊断命令、仓库范围限定、典型工作流和高风险命令处理。
  - 补充 `sync`、`checkout`、`pull`、`commit`、`push`、`forall`、`config`、`continue/abort` 等常见场景。
  - 在 description 中加入 MGIT、mgit、多仓库管理、多仓库状态/同步/分支/提交/推送等触发短语。
- 更新 `CHANGELOG.md`，记录新增 skill。

## 架构决策

### 决策 1: 作为独立 skill 纳入

MGIT 是跨百度 iOS/Android 多仓库工程的高频工具，不绑定单个业务项目，符合“通用、可复用”的 skill 准入标准。

### 决策 2: 优先强调安全工作流

多仓库命令的风险高于单仓库 git 命令。Skill 中把 `mgit status`、`mgit branch --compact`、`--mrepo` 范围限定和高风险命令确认作为核心流程，避免默认操作全部仓库或直接执行 `clean/delete/reset`。

### 决策 3: 不内置脚本

MGIT 自身已经提供稳定 CLI，当前需求主要是命令选择、风险判断和输出解释，使用自然语言指令即可；暂不新增 `scripts/`。

## 排除项及原因

- 不自动执行 `mgit init`：初始化会创建/拉取多仓库工作区，影响范围大，应由用户明确指定。
- 不自动执行 `mgit push`：会影响远端审查系统，必须由用户明确授权。
- 不把本地某个业务工程的 manifest 固化进 skill：manifest 会随工程变化，skill 只沉淀通用判断规则。
