## 架构决策

### 决策 1: 长文档目录作为按需组件，不作为所有报告默认组件

短报告加目录会增加视觉负担，也会挤占正文空间。目录只在章节超过 5 个、包含多组问题/方案/链路/验证结果，或读者需要频繁上下滚动定位时启用。

### 决策 2: 使用锚点跳转，不引入复杂 JS 高亮

目录的核心价值是快速切换章节。锚点跳转配合 `position: sticky` 已能满足需求，避免为当前章节高亮、滚动监听等非必要效果增加复杂度。

### 决策 3: 小屏幕下退化为顶部卡片

固定左侧栏在窄屏上会压缩正文或遮挡内容，因此通过媒体查询让目录变成正文顶部的普通卡片，保证移动端和小窗口可读。

### 决策 4: 使用轻量 token class，而不是引入默认高亮库

报告仍保持单文件、少依赖的原则。模板提供 `tok-key`、`tok-str`、`tok-num`、`tok-cmt` 等基础 class，让生成者手工标注关键 token，即使不引入外部语法高亮库也能提供足够的代码可读性。

### 决策 5: 将晋升材料润色通用化为日常项目总结

晋升材料是低频场景，且“晋升”语义容易让输出过度包装。日常每个需求结束后的总结更通用，也更符合 skill 准入标准。保留原 skill 中“简洁、朴素、可信、不编造收益”的写作原则，但默认输出改为复盘/沉淀口吻。

## 排除项及原因

- 不新增目录自动生成脚本：报告由模型生成时可以直接根据章节写出目录，当前不需要额外脚本。
- 不增加滚动监听高亮：收益有限，增加 JS 复杂度，不符合 html-report 克制交互原则。
- 不强制所有 HTML 报告使用目录：短报告不需要目录，保持页面轻量。
- 不默认引入外部语法高亮库：会增加依赖和体积；当前通过内置 token class 满足基础高亮需求。
- 不保留独立晋升材料 skill：晋升场景仍可通过 `project-summary` 在用户明确说明用途时覆盖，但默认不再以晋升为主，避免 skill 过窄。
