# v0.14.1

## 目标

增强 `delegated-search`，让主 Agent 在执行高输出命令、读取长日志、全仓扫描或跨源检索前，先判断任务是否适合拆给 explorer/subagent，从而减少主线程上下文消耗。

## 变更清单

- `delegated-search` frontmatter 版本升级到 `0.1.2`，描述补充执行前委派判断触发短语。
- `delegated-search` 触发边界增加高输出命令、长材料读取和用户明确要求“先判断能否拆给子 Agent”的场景。
- 新增“执行前委派判断”小节，提供主 Agent 判断模板、优先委派条件和留在主线程的条件。
- README 更新 `delegated-search` 的目录说明、用途和触发示例。
- 两个 manifest 的插件版本升级到 `0.14.1`。
- CHANGELOG 增加 `0.14.1` 版本记录。

## 架构决策

- 不新增独立 skill：这个能力本质仍是委派式搜索、证据收集和上下文隔离，放在 `delegated-search` 内能复用既有触发边界和子 Agent 输出模板。
- 不新增 slash command：执行前判断应由模型在任务宽度、输出规模和可并行性足够明显时主动触发，而不是要求用户每次手动调用。
- 不把委派判断设计成强制拦截器：普通 skill 无法透明拦截每次工具调用，当前版本只沉淀主 Agent 的执行前决策规则。

## 排除项及原因

- 不实现 MCP/SDK 级命令拦截：成本和误伤风险较高，且超出插件 skill 文档能力范围。
- 不要求所有命令前都输出委派判断：简单 `rg`、单文件阅读和小范围验证直接在主线程完成，避免增加交互噪音。
- 不允许子 Agent 替代最终判断：主线程仍负责抽查证据、处理不确定性并向用户交付结论。
