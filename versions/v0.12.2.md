# v0.12.2

## 目标

提高 `ask-user-question` 的自然触发概率。过去 description 过度强调“手动调用”，导致仓库规则明确要求询问、提交前确认、风险操作确认等场景也不容易触发。

## 变更清单

- `ask-user-question` skill 升级到 `0.1.3`。
- frontmatter description 扩展为显式调用、规则要求必须询问、提交前确认、风险操作确认和阻塞性方案选择。
- skill body 同步更新触发边界，保留“不因轻微不确定性打断”的约束。
- `/ask-user-question` command description 从手动不确定性转为阻塞性决策和风险确认。
- README、CHANGELOG、manifest 关键词同步更新。

## 架构决策

- 只改 metadata 和触发说明，不改变底层结构化询问工具调用方式。
- 放宽高价值触发场景，但不把普通澄清、闲聊或低风险取舍纳入自动触发，避免过度打断。

## 排除项及原因

- 不新增脚本：触发概率主要由 skill description 决定，脚本无法改善模型选择 skill 的概率。
- 不修改 AGENTS.md / CLAUDE.md：现有提交前询问规则已经明确，问题在 skill 触发边界过窄。
