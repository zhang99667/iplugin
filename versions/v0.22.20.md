# v0.22.20 - HTML Report 隔离 Eval Runner

## 目标

把 html-report 已有的 eval 定义升级为可执行、可复现、可归档的 forward-test 闭环，同时不增加普通报告生成耗时。

## 变更清单

- 新增 `evals/run_evals.py`，支持完整自动运行、分阶段人工运行和多轮结果汇总。
- 自动运行使用两个独立的临时 Codex 会话，分别负责生成报告和按 rubric 评分。
- 任务 Agent 只接收 prompt、fixtures 和 skill 快照；任务完成并进入确定性校验后才生成 rubric。
- 自动运行快照中的 `check_html_report.py`，并要求 grader 为每条 expectation 提供 `submission/...:line` 证据。
- 用输入、skill 快照和提交物 SHA-256 绑定同一轮评测，防止输入污染、skill 临时修改或评分前替换报告。
- 新增 runner 回归测试，覆盖 rubric 隔离、嵌套 fixture、非法报告拦截、双会话执行和通过率汇总。
- 修复评论模式 eval 的原始 HTML fixture，使其符合当前普通表格圆角契约。
- `html-report` skill 从 `0.6.5` 升级到 `0.7.0`，插件从 `0.22.19` 升级到 `0.22.20`。

## 架构决策

- Runner 属于 skill 维护工具，不进入 `SKILL.md` 的普通报告生成步骤，避免给日常任务增加模型调用和等待时间。
- 自动模式固定使用 Codex CLI 的无状态会话，不通过 shell 拼接命令，减少供应商接口和命令注入的不确定性。
- rubric 延迟生成，而不是仅靠提示要求任务 Agent 不读取评分标准；隔离边界由文件生命周期保证。
- 确定性结构校验先于语义评分，HTML 不合法时直接记录失败，不消耗第二次 grader 调用。
- 保留 `prepare`、`verify`、`finalize` 分阶段接口，便于人工调度或未来接入其他 Agent 编排器，但不为未知供应商提前设计插件层。

## 排除项及原因

- 不加入浏览器视觉回归：用户明确暂缓，且不应与 Eval Runner 混为同一笔改动。
- 不在普通报告生成时自动运行 eval：完整评测包含两次模型调用，只适合维护和版本验收。
- 不自动遍历全部 eval：单次 `run` 显式选择 eval id，批量策略由调用方控制，避免意外产生大量模型调用。
