# v0.21.15 - generate-image 三候选并发筛选

## 目标

把 `generate-image` 的本地 API 流程改成默认并发生成 3 张候选图，再通过视觉检查只保留效果最好的一张，提高一次出图的可用率。

## 变更清单

- `skills/generate-image/scripts/generate_image_client.py`
  - 新增 `--candidates` 参数，支持发起多个并发候选请求。
  - 多候选模式按 `-candidate-<序号>` 保存，避免并发结果互相覆盖。
  - 单个候选失败时不丢弃其他成功候选；全部失败时按鉴权错误或普通生成错误返回。
- `skills/generate-image/SKILL.md`
  - skill 版本升级到 `0.1.5`。
  - 默认命令新增 `--candidates 3`。
  - 明确候选图需要视觉检查，不能用文件大小或返回顺序替代质量判断。
  - 要求最终只保留最佳候选图。
- `skills/generate-image/references/generate-image-apis.md`
  - 同步三候选并发命令和候选留存规则。
- `README.md`
  - Skills 表同步三候选并发筛选能力。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.15`。
- `CHANGELOG.md`
  - 新增 `0.21.15` 版本记录。

## 架构决策

- 并发请求在客户端脚本内实现，避免每次由 agent 手写 shell 并发控制，减少命令编排错误。
- 质量选择不在脚本里用文件大小、返回顺序等伪指标自动判断，而是交给具备视觉检查能力的 agent 执行。
- `--candidates` 默认值保持 `1`，保证脚本直接调用的向后兼容性；skill 默认流程显式传 `--candidates 3`。

## 排除项及原因

- 不接入额外视觉评分 API。当前需求只要求三路并发生成，额外评分链路会增加成本、失败面和接口假设。
- 不改变三条图片生成后端的请求结构。本次只增加候选并发和输出管理。
- 不提交 `outputs/` 下已有生成图片，它们仍是本地产物。
