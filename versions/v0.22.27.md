# v0.22.27 - HTML Report 批注轮次与 Agent 处理回执

## 目标

在离线单文件、没有后端或原生桥接的约束下，减少批注交接的文件导出负担，并让用户能确认 Agent 是否真正处理并回写了 HTML。

## 变更清单

- 页面可见术语统一为“批注”；旧 `kind: 提问 | 注释 | 批注` 仅做数据兼容，新建、展示和交接统一归一为批注。
- 移除提问/注释类型筛选；右键菜单只按选中内容、本段和本节区分作用范围。
- 侧栏主操作改为 `复制批注给 Agent`，零批注时明确禁用；`保存批注版 HTML（备用）` 降为次级入口，Markdown、发布版和清空本轮收进更多菜单。
- 新增持久轮次状态，区分本轮草稿、已复制待处理、Agent 已处理、部分处理和失败，避免只依赖 1.6 秒 toast。
- 新增 `AgentReviewReceipt 0.1.0`：记录 `roundId`、处理时间、总数、处理数、正文是否修改、改动章节和可选逐条结果。
- `inject_annotation_mode.py` 支持：
  - `--processed`：把 HTML 内嵌 `AgentQuestionPack` 转成处理回执。
  - `--processed-round / --processed-count`：为剪贴板交接写入汇总回执。
  - `--receipt-file`：注入自定义逐条处理结果。
- `check_html_report.py` 新增 `--require-review-receipt`，校验回执唯一性、schema、安全转义和状态字段；同一 HTML 禁止同时存在待处理包和已处理回执。
- 发布版物理剥离批注 UI、脚本、待处理包、处理回执、本地路径和定位 ID。
- 同步运行时 helper、组件测试、Gallery、eval、README、manifest 和 skill/reference 契约。

## 架构决策

- 明确采用异步轮次而非伪实时协作：`草稿 -> 复制/备用保存 -> Agent 处理 -> 回执 -> 下一轮`。
- 默认选择剪贴板交接，因为 Agent 可以从包中的绝对路径直接修改原 HTML；文件保存保留为跨会话、跨设备和归档兜底。
- 待处理请求和已处理回执使用两个独立 JSON 节点。新一轮交接移除旧回执，Agent 完成时移除待处理包，避免重复消费和状态歧义。
- `contentChanged` 由 Agent 显式回报，浏览器不根据批注消失、文件时间或 URL 猜测是否修改。
- 回执到达后清理上一轮浏览器草稿；在该回执基础上新增的下一轮草稿通过 `baseReceiptRoundId` 继续保留。

## 排除项及原因

- 不实现后端、localhost 服务、宿主 IPC 或直接调用 Agent；这些超出离线单文件边界。
- 不承诺静默覆盖本地文件、检测下载最终路径或实时订阅磁盘变化；浏览器安全模型无法稳定提供这些能力。
- 不在首期实现回复线程、多人同步、Figma 式锚点、文件句柄持久缓存或内容 hash 证明；本轮先建立可验证的最小轮次闭环。
