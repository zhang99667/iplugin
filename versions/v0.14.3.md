# v0.14.3

## 目标

恢复 Codex telemetry hook 的稳定 wrapper 入口，修复 v0.14.2 中 `hooks/codex-hooks.json` 回退到版本化 `${PLUGIN_ROOT}` 后，旧 session 可能继续引用已删除缓存脚本的问题。

## 变更清单

- `hooks/codex-hooks.json`：Codex PostToolUse hook 恢复使用 `$HOME/.codex/hooks/iplugin-skill-telemetry.py`。
- `scripts/validate-plugin.py`：Codex hook 校验改为要求稳定 wrapper，并显式拒绝 `${PLUGIN_ROOT}/hooks/skill-telemetry.py` 作为 telemetry 入口。
- `README.md`：说明 Codex 第一入口是稳定 wrapper，真实脚本由 wrapper 转发。
- `AGENTS.md` / `CLAUDE.md`：同步维护指南里的 Codex hook 契约。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`：插件版本升级到 `0.14.3`。
- `CHANGELOG.md`：记录本次修复。

## 架构决策

Codex hook 的第一跳必须放在不随插件版本变化的位置。`$HOME/.codex/hooks/iplugin-skill-telemetry.py` 负责动态寻找工作区脚本或最新缓存脚本，避免当前 session 仍持有旧版本 `${PLUGIN_ROOT}` 绝对路径时，因为缓存目录被清理而报 `skill-telemetry.py` 不存在。

## 排除项及原因

- 不修改 Claude Code hook 配置：Claude Code 仍使用 `${CLAUDE_PLUGIN_ROOT}` 和 `matcher: "Skill"`，本次问题只影响 Codex 版本化缓存入口。
- 不改变 telemetry 日志 schema：本次只修入口稳定性，避免把兼容修复扩大成数据迁移。
