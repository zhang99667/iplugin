# Codex Telemetry Wrapper 技术归档

来源文档：

- `/Users/markz/code/baidu/iplugin_hook_posttooluse_analysis.html`
- `/Users/markz/Documents/Obsidian Vault/AI/Codex 与 Claude Code 的 Skill Plugin Hook 机制.md`

归档目的：把 iPlugin PostToolUse telemetry hook 的路径失效问题、稳定 wrapper 方案和验证方式沉淀到版本目录，避免后续升级或回退时再次丢失上下文。

## 摘要结论

iPlugin telemetry 的报错不是 skill 触发错误，也不是 `hooks/skill-telemetry.py` 主体逻辑坏了。根因是 Codex 的 `${PLUGIN_ROOT}` 指向版本化插件缓存，例如：

```text
~/.codex/plugins/cache/personal/iplugin/0.13.0/
~/.codex/plugins/cache/personal/iplugin/0.14.2/
```

当插件升级并清理旧缓存后，旧会话仍可能继续执行启动时解析得到的旧路径：

```text
python3 "${PLUGIN_ROOT}/hooks/skill-telemetry.py"
```

如果该版本缓存目录已经不存在，就会出现：

```text
python3: can't open file '.../hooks/skill-telemetry.py': [Errno 2] No such file or directory
```

推荐修复是稳定 wrapper：Codex hook 的第一入口固定在不带版本号的位置，由 wrapper 再动态定位真实统计脚本。

## Hook 链路

旧链路：

```text
.codex-plugin/plugin.json
  hooks: ./hooks/codex-hooks.json
      |
      v
hooks/codex-hooks.json
  PostToolUse + matcher "*"
      |
      v
python3 "${PLUGIN_ROOT}/hooks/skill-telemetry.py"
      |
      v
~/.codex/skill-usage.jsonl
```

问题点在第三步：`${PLUGIN_ROOT}` 是版本化缓存目录，不是稳定源码目录。

## 根因分析

Codex personal marketplace 的插件加载方式和 Claude Code 不同：

- Claude Code 本地目录市场直接通过软链接读源码，hook 路径通常稳定。
- Codex 会把启用的插件复制到 `~/.codex/plugins/cache/<marketplace>/<plugin>/<version>/`。
- Codex 的 `${PLUGIN_ROOT}` 指向这个缓存副本。
- 插件版本变化后，Codex 会创建新版本缓存并可能清理旧版本。
- 长时间运行的旧会话可能仍持有旧版本的 hook 命令解析结果。

`~/.codex/config.toml` 通常只保存 hook trust 状态和 hash，不直接保存旧版本绝对路径。因此只搜索或修改 `config.toml` 不能根治问题。

## 方案对比

### 方案 A：继续使用 `${PLUGIN_ROOT}`

优点：插件自包含，对不同机器更通用。

缺点：依赖版本化缓存；升级后旧会话或旧路径仍可能报错。

适用：缓存目录稳定、不清理旧版本、很少在长会话中升级插件。

### 方案 B：直接使用源码绝对路径

示例：

```text
/Users/markz/code/tools/iplugin/hooks/skill-telemetry.py
```

优点：本机直接绕开缓存版本号。

缺点：不可迁移；仓库移动后需要改 hook 配置。

适用：个人插件只在固定本机使用。

### 方案 C：稳定 wrapper

示例：

```text
$HOME/.codex/hooks/iplugin-skill-telemetry.py
```

优点：Codex hook 第一入口不再依赖版本化缓存；wrapper 可以优先找源码，再兜底找最新缓存。

缺点：需要维护一个额外入口文件。

适用：频繁升级插件、希望保留 telemetry 又不想污染工具输出。

### 方案 D：禁用 telemetry hook

优点：完全消除 hook 噪声。

缺点：失去 skill 使用率统计。

适用：统计价值不高，优先保持工具输出干净。

## 方案 C 实现设计

稳定链路：

```text
Codex PostToolUse
  |
  v
$HOME/.codex/hooks/iplugin-skill-telemetry.py
  |
  +-- IPPLUGIN_TELEMETRY_SCRIPT
  |
  +-- /Users/markz/code/tools/iplugin/hooks/skill-telemetry.py
  |
  +-- ~/.codex/plugins/cache/personal/iplugin/*/hooks/skill-telemetry.py
      选择最高版本且存在的脚本
```

分层职责：

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| Codex hook 配置 | `hooks/codex-hooks.json` | 只调用稳定 wrapper，不直接引用 `${PLUGIN_ROOT}` |
| 稳定 wrapper | `$HOME/.codex/hooks/iplugin-skill-telemetry.py` | 定位真实 telemetry 脚本；失败时静默退出 |
| 真实统计脚本 | `hooks/skill-telemetry.py` | 读事件、识别 skill、写入 `~/.codex/skill-usage.jsonl` |
| 安装/刷新流程 | `codex plugin add iplugin@personal` 或手动复制 wrapper | 确保缓存和稳定入口同步 |

当前仓库中的 wrapper 源码位于：

```text
hooks/iplugin-skill-telemetry.py
```

Codex hook 配置应使用：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$HOME/.codex/hooks/iplugin-skill-telemetry.py\"",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

注意：这里使用 `$HOME`，因为 shell 会展开它；不要在引号内使用 `~`。

## 安装与升级注意

首次引入 wrapper：

```bash
mkdir -p "$HOME/.codex/hooks"
cp /Users/markz/code/tools/iplugin/hooks/iplugin-skill-telemetry.py \
  "$HOME/.codex/hooks/iplugin-skill-telemetry.py"
chmod +x "$HOME/.codex/hooks/iplugin-skill-telemetry.py"
```

插件源码变更后：

```bash
codex plugin add iplugin@personal
```

如果 hook 命令字符串发生变化，需要通过 Codex 的 `/hooks` 重新 trust。只改 wrapper 内部逻辑时，是否需要重新 trust 取决于 Codex 对 hook 命令 hash 的计算范围；实践上应至少做一次手动 smoke check。

## 验证方式

验证 wrapper 可以找到真实脚本并写日志：

```bash
printf '{"tool_input":{"skill":"html-report"},"hook_event_name":"PostToolUse","tool_name":"Skill","session_id":"wrapper-test"}' \
  | python3 "$HOME/.codex/hooks/iplugin-skill-telemetry.py"
tail -1 "$HOME/.codex/skill-usage.jsonl"
```

预期最后一行包含：

```json
{"skill": "html-report", "session": "wrapper-test"}
```

如果真实 telemetry 脚本不存在，wrapper 应静默退出，不再出现 `can't open file` 报错。

## 后续防回退规则

- `hooks/codex-hooks.json` 不应再使用 `${PLUGIN_ROOT}/hooks/skill-telemetry.py` 作为 telemetry 第一入口。
- `scripts/validate-plugin.py` 应校验 Codex telemetry 使用 `$HOME/.codex/hooks/iplugin-skill-telemetry.py`。
- `README.md`、`AGENTS.md`、`CLAUDE.md` 中关于 Codex hook 的描述要和 validator 保持一致。
- 修改 hook 配置后，必须运行 `python3 scripts/validate-plugin.py`。
