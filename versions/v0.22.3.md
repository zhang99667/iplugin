# v0.22.3 - DataPilot 跑数结果闭环

## 目标

把 `datapilot-sql-runner` 从“跑 SQL 并回收任务 ID”的页面经验型 skill，调整为“通过 DataPilot MCP 产出结果文件，并可直接生成商业 AB 透视表”的结果闭环 skill。

## 变更清单

- `skills/datapilot-sql-runner/SKILL.md`
  - skill 版本升级到 `0.1.3`。
  - frontmatter 描述改为 MCP 结果闭环，明确提交 SQL、查状态、下载判断、下载结果和透视表产出是默认主路径。
  - 主体大幅瘦身，只保留输入收集、SQL 预处理、MCP 主流程、心跳等待下载、结果产出和 Chrome 回退入口。
  - 结果产出阶段补充联动 `nad-acx-pivot-table` 的规则：下载结果字段匹配商业 AB 实验结构，或用户明确要求透视表时，直接生成 xlsx。
- `skills/datapilot-sql-runner/references/chrome_fallback.md`
  - 新增 Chrome 兜底文档，承接 DataPilot 页面连接、Monaco 粘贴、任务 ID 提取、页面状态解析和常见坑。
- `README.md`
  - 更新 `datapilot-sql-runner` 能力说明，突出 MCP 等待下载和透视表产出。
- `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`
  - 插件版本升级到 `0.22.3`。
  - 描述、关键词和默认提示同步 DataPilot 结果闭环定位。
- `CHANGELOG.md`
  - 记录本次指令重构。

## 架构决策

- Chrome 经验不再占用 `SKILL.md` 主上下文。它仍然有价值，但只在 MCP 不可用、页面专属设置必须保留或需要运行中心辅助定位时读取。
- MCP 是唯一默认主路径。提交、状态查询、下载判断和下载结果都优先由 MCP 负责，避免重新落回脆弱的页面编辑器流程。
- 结果交付前移。用户要求“跑完出结果”时，不停在任务 ID，而是用心跳等待下载结果；结果字段适配商业 AB 实验结构时，直接调用透视表 skill 生成 xlsx。

## 排除项及原因

- 不修改 DataPilot MCP 工具实现：本次只调整 skill 调度和文档结构。
- 不复制 `nad-acx-pivot-table` 的详细脚本用法：透视表生成仍以该 skill 为单一维护入口，避免两处规则漂移。
- 不删除 Chrome 关键词：Chrome 仍是兜底路径和历史触发语义的一部分，但不再是主定位。
