# v0.8.8

## 目标

把 `karpathy-guidelines` 从“用户点名时使用”的风格准则，调整为编码、修 bug、重构和 code review 任务中的默认工程护栏，减少过度设计、无关改动和不可验证实现。

## 变更清单

- `karpathy-guidelines` 升级到 `0.1.2`
  - frontmatter description 改为任务上下文触发：实际写代码、修 bug、重构、code review 或实现方案落地时使用
  - 保留用户点名“按 Karpathy 准则”作为显式入口
  - 明确普通代码解释、闲聊、文档整理或无需改代码的问答不单独触发
- 插件版本升级到 `0.8.8`，同步更新 Claude Code 与 Codex manifest

## 架构决策

- `karpathy-guidelines` 本质是编码行为约束，不是单独产物型能力；模型应在需要动代码或 review 时主动加载。
- 触发边界仍排除无需改代码的问答，避免把轻量解释任务变成完整工程流程。

## 排除项及原因

- 不调整其他 skill：本次只修正 `karpathy-guidelines` 的 under-trigger 风险。
- 不新增脚本或测试框架：这是触发描述和行为边界优化，现有仓库 validator 足够覆盖结构一致性。
