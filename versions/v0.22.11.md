# v0.22.11 - 活跃与退役 Skill 分层

## 目标

把长期零调用、已不值得继续占用插件触发上下文的 skill 从活跃目录中移出，同时保留可追溯实现。建立清晰、可校验的活跃/退役目录边界，避免废弃能力继续进入 Claude Code 或 Codex 的可发现 skill 列表。

## 退役依据

- 统计 `2026-06-01` 至 `2026-07-20` 的 Codex 主任务 telemetry，并结合 Claude skill 日志复核。
- `session-rename` 在 Codex 与 Claude 中均无实际任务命中，并且只适用于 Claude Code 会话标题，缺少跨平台继续维护价值。
- `html2md` 当前同样没有 telemetry 命中，但用户确认继续保留；零调用只作为评估信号，不自动触发退役。
- 其他低频 skill 至少存在实际任务命中；低频本身不足以判定废弃，本次不扩大退役范围。

## 变更清单

- 将 `skills/session-rename/` 整体移动到 `deprecated-skills/`；`skills/html2md/` 保持活跃。
- 为归档的 `session-rename/SKILL.md` 增加 `deprecated`、`deprecated_in` 和 `deprecated_reason` 元数据。
- 新增 `deprecated-skills/README.md`，记录退役清单、原因、替代方式和恢复约束。
- 从 README 活跃 Skills 表、插件说明、manifest 关键词及 Codex 默认提示中移除退役能力。
- 更新 `AGENTS.md` 与 `CLAUDE.md`，增加统一的退役流程和提交前检查项。
- 扩展 `scripts/validate-plugin.py`，校验：
  - `skills/` 与 `deprecated-skills/` 不重名；
  - 归档 frontmatter 包含完整退役元数据；
  - README 活跃表与归档表分别匹配实际目录；
  - 退役名称不残留在 manifest 关键词；
  - Codex manifest 只扫描 `./skills/`。
  - 插件版本第一位保持 `0`，第二位等于活跃与退役 skill 总数。
- 两个平台 manifest 同步升级到 `0.22.11`。

## 架构决策

- `skills/` 是唯一的活跃能力扫描根；退役目录必须位于它之外，不能使用 `skills/deprecated/`，避免递归发现规则变化后重新注册废弃能力。
- 退役采用移动而非删除，保留完整目录和最后一版说明，便于历史追溯与低成本恢复。
- README 的 `## Skills` 只列活跃能力，`## Deprecated Skills` 单独列归档；用户可见能力与历史记录不混在同一张表中。
- 历史 CHANGELOG 与旧版本规划文档继续保留当时路径和能力描述，不回写历史。
- 插件版本中间位记录累计新增 skill 数，只在新增 skill 时递增；退役不会回退该计数，也不会升级第一位，因此从 `0.22.10` 升级到 `0.22.11`。

## 排除项及原因

- 不因调用率低而批量退役其他 skill；专业、低频能力可能仍有高价值，需要结合替代方案和实际工作流判断。
- 不删除 telemetry 历史记录；历史事件用于后续趋势对比，即使对应 skill 已归档也应保留。
- 不把归档 skill 继续打包成可手动调用入口；需要恢复时先重新评估触发边界，再移回活跃目录并正式发布。
- 不修改 `session-rename` 的内部工作流和 references；归档保存的是退役时快照。
