# v0.21.11 - generate-image 接口链路路由修复

## 目标

修复 `generate-image` skill 的路由歧义：用户明确说 `gptimage`、`gptimg2`、`gpt-image-2`、`banana2` 等接口链路时，应默认使用 skill 内置的本地 API 客户端，并按 `GENERATE_IMAGE_API_KEY` 规则处理鉴权；不能被平台内置图片生成能力接走。

## 变更清单

- `skills/generate-image/SKILL.md`
  - skill 版本升级到 `0.1.3`。
  - 目标说明补充 `gptimage` 等接口链路触发词。
  - 执行方式选择中明确：只有泛泛出图且未指定接口链路时，才优先使用平台内置图像能力。
  - 用户明确指定 `gptimage` / `gptimg2` / `gpt-image-2` / `banana` / `banana2` / `responses` / Comate / Gemini，或指定 API / backend / base URL / 本地保存 / 可复现 CLI 时，必须走 `generate_image_client.py`。
- `README.md`
  - Skills 表同步说明明确指定接口链路时必须走通用 API 客户端。
- `.claude-plugin/plugin.json` / `.codex-plugin/plugin.json`
  - 插件版本升级到 `0.21.11`。
- `CHANGELOG.md`
  - 新增 `0.21.11` 版本记录。

## 架构决策

- 保留“泛泛生成图片可用平台内置能力”的路径。它适合不关心私有链路和本地可复现输出的普通出图请求。
- 把接口链路词作为强路由信号，而不是只作为 prompt 清洗词。用户点名 `gptimage` / `gptimg2` 时，意图是使用该 skill 的 API 客户端和密钥流程。
- 不新增脚本参数或额外配置。现有 `generate_image_client.py` 已支持 `gptimg2`、`gpt-image-2`、`banana2` 等别名，本次只修正文档驱动的 agent 决策。

## 排除项及原因

- 不移除平台内置出图路径。普通出图场景继续保持低摩擦。
- 不修改 API 客户端代码。当前问题来自 skill 路由说明不够强，不是脚本实现缺陷。
- 不调整 manifest 描述和关键词。现有关键词已覆盖图片生成和 `gpt-image`，本次只需要升级版本。
