# v0.13.3

## 目标

提升 `html-report` 输出稳定性，减少 HTML 报告生成时出现代码块缺少高亮、窄屏/分屏显示不全，以及长文档目录只能展开不能折叠的问题。

## 变更清单

- `html-report` skill 升级到 `0.2.15`。
- `highlight_code.py` 增加 `sql`、`json`、`yaml`、`bash` 支持，并补充常见语言/后缀别名映射。
- `highlight_code.py` 增加 `--engine auto/pygments`，支持在本机 Pygments 可用时使用增强静态预渲染，默认仍为零依赖 `builtin`。
- `css-template.md` 增加全局 `box-sizing`、窄屏响应式、打印样式、横向滚动保护和触屏可见的复制按钮规则。
- 长文档目录模板改为 `<details class="toc-details" open>`，默认展开，点击目录标题可折叠。
- `check_html_report.py` 增加 viewport、响应式/打印样式、复制按钮、受支持语言、`tok-*` / Pygments inline style 高亮和可折叠目录结构检查。
- `visual-rules.md`、`content-rules.md`、`SKILL.md` 同步新的高亮、目录和窄屏显示要求。
- README 与两个 manifest 版本升级到 `0.13.3`。

## 架构决策

- 继续保持 `SKILL.md` 轻量，只放触发、导航和最短流程；高亮、目录和 CSS 细节留在 references 与脚本里。
- 代码高亮优先靠确定性脚本扩展语言覆盖面，而不是要求模型手工写大量 `tok-*` span；增强模式只使用本机 Pygments 预渲染，最终报告仍是静态单文件。
- 目录折叠使用原生 `<details open>`，避免引入额外 JS 状态和兼容性问题。
- 校验脚本只做结构性检查，不评价视觉审美；它负责拦截容易重复出现的生成漂移。

## 排除项及原因

- 不引入 highlight.js、Prism 或 CDN 到最终报告：报告仍保持离线单文件输出；若后续使用 Shiki/Prism，也只能作为本地生成阶段预渲染工具。
- 不加入复杂目录滚动高亮：用户当前反馈是可折叠和稳定显示，原生目录已经足够。
- 不重写整体 HTML 视觉体系：本次是稳定性 patch，避免牵动无关报告样式。
