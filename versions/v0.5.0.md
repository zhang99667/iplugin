# v0.5.0

## 目标

新增一个面向 Android 矩阵产品差异化开发的标记助手，把 KU 文档中的 V3.0 差异化标记规范沉淀成可复用 skill。用户在处理手百基线和矩阵差异化改动时，可以直接要求补齐 `@LiteAdd`、`@LiteModified`、`@LiteDelete`、`@BaseSplit` 等标记。

## 变更清单

- 新增 `lite-diff-marker` skill，版本 `0.1.0`
- 覆盖 Java / Kotlin、XML、脚本配置三类文件的标记规则
- 按新增、修改、删除三类差异化改动给出决策流程和示例
- 明确 Java / Kotlin 使用 V3.0 块注释格式，减少对基线代码的额外 Git Diff
- 补充 import 搜索、标记配对、嵌套块注释规避等落地检查项
- 插件版本升级到 `0.5.0`，同步更新 Claude Code 与 Codex manifest 的描述和关键词

## 架构决策

- 将规范写成操作型 skill，而不是只保存 KU 原文，便于在真实仓库中根据 diff 自动判断新增、修改、删除。
- Skill 保持通用，不绑定具体业务仓库；通过 `git diff`、文件路径、before/after 片段等输入识别改动。
- Java / Kotlin 注解 import 不写死为唯一包名，要求先搜索项目已有用法，避免不同工程注解包名不一致时引入错误依赖。
- 对 XML 修改采用直接包裹修改后 tag 的规则，不强制保留基线 XML，因为原规范已明确 XML 无需区分基线和矩阵代码。

## 排除项及原因

- 不实现自动解析和批量重写脚本；目前先沉淀人工可控的标记流程，避免错误分类导致大范围代码污染。
- 不复制 KU 文档全文；只保留执行时需要的判断规则、格式和示例，降低 skill 体积。
- 不默认运行编译；不同 Android 仓库构建耗时和环境差异较大，由实际使用场景决定是否验证。
