# remote-android-build v0.1.5

## 目标

给 rsync 增加可选的 `--delete-excluded`，用来清掉远端残留的 ignore 目录。默认仍关闭，避免每次同步都删掉远端 `build/` 和 `.gradle/`。

## 变更清单

- `remote-build.zsh`
  - 新增 `--delete-excluded` 命令行开关。
  - 新增 `DELETE_EXCLUDED` 配置项，默认 `0`。
  - `--print-config` 输出 `DELETE_EXCLUDED`。
- `init-project.zsh`、`remote-build.env.example`
  - 生成配置默认写出 `DELETE_EXCLUDED="0"`。
- `README.md`、`CHANGELOG.md`、`versions/README.md`、`AGENTS.md`、`CLAUDE.md`
  - 说明何时临时打开这个开关。
- `docs/remote_android_build_implementation_plan_v0_1.md`
  - 补充默认不加 `--delete-excluded` 的原因和残留 `build/` 处理方式。

## 架构决策

- 默认不加 `--delete-excluded`。ignore 里的 `build/`、`.gradle/` 是远端增量编译缓存，日常同步必须保留。
- 关掉 overlay 或切分支后，本地模块消失，远端残留 `build/` 会让 rsync 报 `Directory not empty`。这时再临时打开开关。
- 命令行 `--delete-excluded` 覆盖配置文件，方便只清一次，不必改项目配置。

## 排除项及原因

- 不把 `--delete-excluded` 设成默认。打开后会清远端 `.gradle/`，下次编译变慢。
- 不自动识别 `unlinkat: Directory not empty` 再重试。这次只暴露显式开关。
- 不修改已有项目的 `.remote-build.zsh`。旧配置没有这项时仍按默认 `0` 处理。

## 验证记录

- 通过：`zsh -n tools/remote-android-build/init-project.zsh`
- 通过：`zsh -n tools/remote-android-build/remote-build.zsh`
- 通过：`tools/remote-android-build/remote-build.zsh --help`
- 通过：未设置 `DELETE_EXCLUDED` 时 `--print-config` 输出 `DELETE_EXCLUDED=0`
- 通过：`--delete-excluded --print-config` 输出 `DELETE_EXCLUDED=1`
