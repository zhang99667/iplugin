# remote-android-build v0.1.4

## 目标

让远端编译只认一条 `REMOTE_COMMAND`，在 `REMOTE_ROOT` 下执行。默认生成完整命令，不再用 `TASK` 拼 `./gradlew`。

## 变更清单

- `remote-build.zsh`
  - 远端编译入口改为 `REMOTE_COMMAND`。
  - 未设置时默认为 `./gradlew :app:assembleDebug`。
  - 删除对 `TASK` 和 `REMOTE_GRADLE_ARGS` 的读取与拼装。
  - `--print-config` 只输出 `REMOTE_COMMAND`，不再输出 `TASK` / `REMOTE_GRADLE_ARGS`。
- `init-project.zsh`、`remote-build.env.example`
  - 生成配置默认写出 `REMOTE_COMMAND="./gradlew :app:assembleDebug"`。
  - 不再生成 `TASK` 或 `REMOTE_GRADLE_ARGS`。
- `README.md`、`CHANGELOG.md`、`versions/README.md`
  - 同步记录单命令入口和执行目录。
- `docs/remote_android_build_implementation_plan_v0_1.md`
  - 更新远端编译入口说明。

## 架构决策

- 远端只执行一条命令。flavor、64 位参数或包装脚本都写进 `REMOTE_COMMAND`，不再保留 `TASK` 这条第二入口。
- 执行目录固定为 `REMOTE_ROOT`。同步目录和编译 cwd 不拆开。
- 通用工具默认值仍是 `./gradlew :app:assembleDebug`。手百 64 位参数放在项目配置里。
- SSH 非交互会话通常不加载 alias。脚本不尝试展开本地或远端 alias。

## 排除项及原因

- 不把 `run64` 写进工具默认值。它是个人脚本，默认入口仍是 `./gradlew`。
- 不新增本地后续钩子。本次只替换远端编译命令。
- 不在脚本里兼容旧 `TASK`。已有项目需要把原来的 task 收进 `REMOTE_COMMAND`。
