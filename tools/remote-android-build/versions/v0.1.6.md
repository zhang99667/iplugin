# remote-android-build v0.1.6

## 目标

修正 `--delete-excluded` 误删远端 `local.properties` 的问题。同步前只清理 `build/` 中间产物，不再把 rsync `--delete-excluded` 传给 ignore 全表。

## 变更清单

- `remote-build.zsh`
  - 默认在同步前清本地已消失模块的残留目录，避免 `Directory not empty`。
  - `--delete-excluded` / `DELETE_EXCLUDED=1` 只清远端全部 `build/`，相当于远端 clean。
  - 两种模式都不删除 `local.properties`、`.gradle/` 或其他 ignore 文件。
- `init-project.zsh`、`remote-build.env.example`、README、CHANGELOG、实施方案
  - 说明这个开关只作用于 `build/` 中间产物。

## 架构决策

- rsync `--delete-excluded` 太猛：ignore 里的 SDK 配置和 Gradle 缓存也会被删。
- 真正卡住同步的是已消失模块里的 `build/`。只删这些目录就够。
- 还在用的模块默认保留 `build/`，继续做增量编译。

## 排除项及原因

- 不默认清全部 `build/`。那会让每次构建都接近 clean。
- 不清理 `.gradle/`。那是远端增量编译缓存，不是这次卡住同步的原因。
- 不恢复被上次 `--delete-excluded` 删掉的文件。那是远端机器私有配置，需要各自补回。

## 验证记录

- 通过：`zsh -n tools/remote-android-build/init-project.zsh`
- 通过：`zsh -n tools/remote-android-build/remote-build.zsh`
- 通过：`tools/remote-android-build/remote-build.zsh --help`
- 通过：默认 `--print-config` 仍输出 `DELETE_EXCLUDED=0`
- 通过：`--delete-excluded --print-config` 仍输出 `DELETE_EXCLUDED=1`
