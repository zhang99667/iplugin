# remote-android-build v0.1.3

## 目标

修正远端镜像目录保留旧 Git 元数据导致的分支、HEAD、暂存区和构建版本信息不一致问题。

## 变更清单

- `remote-build.zsh`
  - 新增 `SYNC_GIT_METADATA` 配置，默认值为 `1`。
  - 默认同步 `.git/.mgit`，并用 rsync include 规则覆盖旧 `.remote-buildignore` 中的 Git 元数据排除项。
  - 设置 `SYNC_GIT_METADATA=0` 时显式排除 `.git/.mgit`，保留远端自己的 clone 元数据。
  - `--print-config` 输出新增配置项。
- `init-project.zsh`、`remote-build.env.example`
  - 生成配置和示例配置新增 `SYNC_GIT_METADATA` 注释。
- `remote-buildignore.template`
  - 移除 `.git/`、`.mgit/` 默认排除项。
- `README.md`、`CHANGELOG.md`、`versions/README.md`
  - 同步记录默认同步 Git 元数据的行为变化。
- `docs/remote_android_build_implementation_plan_v0_1.md`
  - 更新架构决策和风险处理说明。

## 架构决策

- 远端 `REMOTE_ROOT` 是本地工作区镜像，因此默认应让分支、HEAD、index 和构建读取到的 Git 信息跟随本地。
- 旧项目可能已经生成包含 `.git/`、`.mgit/` 的 `.remote-buildignore`，所以主脚本必须在默认模式下用 include 规则覆盖旧排除项，不能只改模板。
- 对大仓库、Git worktree 或明确想保留远端 clone 的场景，保留 `SYNC_GIT_METADATA=0` 作为显式退路。

## 排除项及原因

- 不自动清理远端仓库状态。`REMOTE_ROOT` 由 rsync 镜像维护，额外执行 `git clean` 或 `git reset` 会扩大破坏面。
- 不自动在远端执行 `git switch`。同步 `.git/.mgit` 已经能保持远端镜像状态，额外切分支会和本地未提交改动、暂存区状态冲突。
- 不覆盖已经存在的项目级 `.remote-build.zsh` 或 `.remote-buildignore`。主脚本兼容旧 ignore 文件，项目配置仍由用户维护。
