核心结论

z-agent 的主设计不是接管原始 codex / claude 命令，而是让用户显式通过 zagent codex 或 zagent claude 启动一次可记录的 Agent 会话。wrapper 注入 pane 身份，hook 回写 session 元数据，Ghostty snapshot 把终端窗格和会话绑定，restore 最后只执行白名单内的 resume 命令。

主入口 显式 wrapper
只有 zagent codex/claude 进入注入链路，原始命令不被替换。
状态核心 workspace_state.json
保存 active_terminals、latest_workspace 和一份 previous 快照。
恢复安全 结构化 argv
自动恢复只允许 codex resume <id> 和 claude --resume <id>。
边界 Ghostty 集成仍需实测
单测覆盖纯逻辑，真实 GUI 自动化和 macOS Automation 权限需要手动验证。

完整主线

完整链路可以压缩成一句话：安装只生成 hook 入口，真实运行时由 zagent codex/claude 显式启动 Agent，wrapper 和 hook 共同填充状态，snapshot 绑定 Ghostty pane，restore 经过内部白名单校验后直接执行安全命令。

1. 入口分发：先判断是不是 Agent 快捷入口

准备阶段：包入口和 CLI 入口

pyproject.toml 把命令行入口注册为 zagent = "z_agent.cli:main"。进入 main() 后，代码先看第一个参数是不是 codex 或 claude。如果是，就直接走 wrapper 快捷入口；如果不是，才进入 argparse 子命令树。

执行阶段：这里直接决定两条世界线：zagent codex 是“启动真实 Agent 并注入元数据”；zagent install/snapshot/restore 是普通管理命令。

2. 安装阶段：只生成 hook 文件，不接管原始命令

准备阶段：生成安装计划

zagent install codex 不会创建 bin/codex，也不会生成需要 source 的 PATH wrapper。它只写入 hook ingest 脚本和原生 hook 配置示例。这样原始 codex / claude 仍保持原样，只有显式输入 zagent codex 才进入记录链路。

def mutate_state(mutator: Callable[[StateDict], Any], root: Path | None = None) -> StateDict:
    path = state_file_path(root)
    with _lock(path):
        try:
            state = _read_without_lock(path)
        except StateError:
            state = empty_state()
        mutator(state)
        _write_without_lock(path, state)
        return state

_restore() 总是先读 latest_workspace 并构建内部计划。命令行不再暴露查看计划、只输入不回车或只打印脚本的模式；进入 GhosttyAdapter 前必须跑 assert_plan_executable()。

def validate_restore(restore: Any) -> tuple[bool, str]:
    if not isinstance(restore, dict):
        return False, "缺少结构化恢复命令"
    agent = restore.get("agent")
    argv = restore.get("argv")
    if agent == "codex" and isinstance(argv, list) and len(argv) == 3:
        if argv[0] == "codex" and argv[1] == "resume" and _is_safe_session_token(str(argv[2])):
            return True, "通过"
    if agent == "claude" and isinstance(argv, list) and len(argv) == 3:
        if argv[0] == "claude" and argv[1] == "--resume" and _is_safe_session_token(str(argv[2])):
            return True, "通过"
    return False, "恢复命令不在白名单内"

执行阶段：build_restore_script():108-150 再次构建并校验 plan，只为 allowed=True 的 pane 生成 input text。普通 shell pane、低置信 pane、旧字符串 restore_cmd 都不会自动输入命令。

副作用：restore_workspace():250-262 生成恢复脚本后直接调用 osascript，不再保留额外执行模式。
