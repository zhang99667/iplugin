z-agent Ghostty 工作区恢复技术方案

本方案定义 z-agent 的本期目标：记录 Ghostty window / tab / split / terminal pane 的工作区快照，并把每个 pane 与对应 Agent session 绑定；恢复时重建布局，并在原 pane 位置执行 Codex 或 Claude Code 的原生 resume。

技术方案 · 工作区恢复 z-agent v0.1.0 macOS · Ghostty 布局接口：Ghostty AppleScript Codex / Claude Code 分端接入 版本记录：../versions/v0.1.0.md 更新日期：2026-06-13 状态：方案待 review，代码待对齐

TL;DR

目标模型 恢复工作区快照 z-agent 通过 Ghostty AppleScript 记录 window、tab、split、terminal pane 布局，并将每个 pane 绑定到当时运行的 Agent session。
分端支持 Codex / Claude Code 拆开 zagent install codex 与 zagent install claude 分别生成 agent 原生 hook 模板和 ingest 入口；启动仍显式使用 zagent codex / zagent claude。
单文件状态 workspace_state.json 本期只维护一个当前状态文件，包含 active terminals、latest workspace 和一份 previous workspace 回退缓存。
安全默认 review first install 不接管原始 codex/claude 命令，restore 默认只输出工作区恢复计划；本轮不会替用户执行恢复。
边界明确 恢复布局与 session 恢复目标是 Ghostty 布局、pane 的工作目录和 Agent 原生 session；不恢复进程内存、PTY、未完成 tool call，也不读取对话转录正文。

实施边界

设计项 最终实现 边界说明
项目形态 主体放在 iPlugin monorepo 的 tools/z-agent 独立工具项目中。 它是可运行工具，未来可以单独打包、测试、发布，也可以扩展为 Agent 工作区编排工具。
恢复对象 恢复单位是一次 Ghostty 工作区快照，快照内的每个 terminal/pane 独立携带恢复所需元数据。 快照包含 window、tab、terminal、split_tree、cwd、agent、session_id、restore_cmd 和采集时间。
Ghostty 控制接口 通过 osascript 调用 Ghostty AppleScript dictionary 读取和重建 GUI 布局。 workspace snapshot 的 window / tab / terminal 信息以 AppleScript 返回的对象模型为准。
Codex / Claude Code 支持 主程序复用同一套核心模块，install 和配置按 agent 拆分。 每个 agent 维护自己的安装路径、hook 模板、session 目录和 resume 参数。
zagent snapshot 通过 osascript 采集 Ghostty 当前布局，并把 AppleScript terminal 与当前 terminal 记录绑定成可恢复快照。 快照写入 workspace_state.json 的 latest_workspace，供 zagent restore 使用。
zagent restore 读取最近一次快照，调用 osascript 重建布局并输入 resume 命令。 恢复动作会打开窗口、创建 tab/split 并输入命令，执行前由内部白名单拦截不安全命令。
Shell 入口 不生成 PATH wrapper，不自动写入 .zshrc。 避免未经确认接管用户原始 codex/claude 命令。
自动化 hooks 实现 agent 原生 hook ingest 与 post-hook 两层扩展点；hook 事件用于更新 workspace_state.json 中当前 terminal 的 session_id、session_file 和 restore_cmd。 hook 不追加长期历史，只维护恢复最新工作区所需的当前 terminal 状态。

时机链路

关键时机分成三段：启动 Agent 时生成 terminal 身份并注入运行环境；Agent 运行中由 hook 回写 session；采集快照时通过 Ghostty AppleScript 读取布局并固化到 latest_workspace。恢复只读取这份快照。

数据 / 动作 生成或读取时机 来源 写入 / 注入位置 后续读取方
terminal_key wrapper 被 shell 命中后、真实 Agent 启动前。 z-agent wrapper 生成的随机稳定标识。 写入子进程环境变量 Z_AGENT_TERMINAL_KEY，同时写入当前 terminal 的 name/title marker。 hook ingest 通过 env 读取；snapshot capture 通过 Ghostty AppleScript 读取 terminal name/title marker。
run_id wrapper 启动本次 Agent 进程时。 z-agent wrapper 为本次启动生成。 写入子进程环境变量 Z_AGENT_RUN_ID，用于诊断和一次启动链路关联。 hook ingest 可读取，用于日志和低置信度匹配辅助。
cwd wrapper 启动前；snapshot capture 时再次读取。 wrapper 的当前工作目录；Ghostty AppleScript 的 terminal working directory。 写入 Z_AGENT_CWD 和 active_terminals，快照时写入 latest_workspace。 restore 用它设置恢复后的 initial working directory；匹配失败时也可作为兜底条件。
terminal marker 真实 Agent 启动前。 由 terminal_key 拼成 __zagent_terminal_xxx__。 通过终端标题控制序列写入当前 Ghostty terminal 的 name/title 元数据。 zagent snapshot capture 通过 AppleScript 读取，用来识别这个 pane 对应哪个 terminal_key。
session_id Agent 运行后触发原生 hook 时。 Codex / Claude Code hook payload，或 hook payload 中的 transcript/session 文件路径。 由 zagent hook ingest 更新到 workspace_state.json.active_terminals[terminal_key]。 snapshot capture 合成快照时读取；restore 最终生成 codex resume 或 claude --resume。
latest_workspace 执行 zagent snapshot capture 时。 Ghostty AppleScript 布局数据 + active_terminals 里的 Agent session 状态。 覆盖写入 workspace_state.json.latest_workspace。 zagent restore 读取它，重建 window / tab / terminal split，并输入 resume 命令。

实现契约

本节定义代码实现必须遵守的边界。实现者按下面的模块职责拆分即可落地；各模块之间只通过命令参数、环境变量、Ghostty AppleScript 返回值和 workspace_state.json 交换信息。

模块 输入 必须完成的动作 输出 / 副作用 失败处理
install zagent install codex 或 zagent install claude、安装目录。 生成 agent hook ingest 脚本和原生 hook 配置模板。 写入安装目录，不自动修改 shell profile，不生成同名 PATH wrapper。 需要 z-agent 记录会话时，显式使用 zagent codex 或 zagent claude。
wrapper 用户输入的 codex / claude 命令、当前 cwd、真实 CLI 路径。 生成 terminal_key 和 run_id；写 terminal marker；设置 Z_AGENT_* 环境变量；启动真实 CLI。 真实 Agent 进程继承环境变量；workspace_state.json.active_terminals[terminal_key] 可先写入 agent、cwd、marker、last_seen_at。 真实 CLI 启动失败时透传退出码；状态写入失败时输出 warning，不阻止用户启动 Agent。
hook ingest agent 原生 hook 的 stdin JSON，以及 wrapper 注入的 Z_AGENT_TERMINAL_KEY、Z_AGENT_CWD。 提取 session_id、transcript/session 文件路径、agent、cwd；生成 restore_cmd。 更新 workspace_state.json.active_terminals[terminal_key]。 缺少 terminal_key 时拒绝写入并提示 wrapper 未生效；缺少 session_id 时保留 cwd 和 agent，但标记为不可 resume。
state store active terminal 更新、snapshot capture 结果、restore 读取请求。 维护单文件 workspace_state.json；写入前读旧状态；更新时保留未涉及字段；capture 前把旧 latest_workspace 移到 previous_workspace。 原子写入状态文件，建议采用临时文件 + rename；并发写入使用 lock 文件或平台文件锁。 JSON 解析失败时先备份坏文件，再初始化空状态并提示用户；写入失败时返回非零退出码。
ghostty adapter Ghostty AppleScript 对象模型、latest_workspace、restore plan。 通过 osascript 读取 windows / tabs / terminals；读取 terminal id、name、working directory；恢复时创建 window、tab、split terminal 并输入命令。 capture 输出布局树；restore 执行 AppleScript。 Automation 权限缺失、Ghostty 未运行、AppleScript 字段缺失时输出明确错误；restore 不应执行半截命令后静默成功。
restore planner workspace_state.json.latest_workspace。 生成内部恢复计划；校验 restore_cmd 只允许 codex resume <id> 或 claude --resume <id>；区分 Agent terminal 和普通 shell terminal。 恢复前校验计划；校验通过后调用 Ghostty adapter。 没有 latest_workspace 时提示先执行 zagent snapshot capture；命令白名单校验失败时拒绝执行。
字段 / 标识 格式 生命周期 实现要求
terminal_key za_terminal_ + 随机短 id，示例：za_terminal_a1b2c3d4。 一次 terminal/Agent 启动期间稳定；写入状态后可被快照长期引用。 必须避免不同 terminal 冲突；不得包含 shell 特殊字符。
terminal marker __zagent_terminal_<id>__。 wrapper 启动真实 Agent 前写入当前 terminal name/title。 snapshot capture 优先用它绑定 terminal；写入方式需要在真实 Ghostty 上验证能否通过 AppleScript 读取。
Z_AGENT_TERMINAL_KEY 值等于 terminal_key。 只存在于真实 Agent 进程及其子进程环境中。 不写入 .zshrc；hook ingest 通过环境变量读取。
restore_cmd codex resume <session_id> 或 claude --resume <session_id>。 hook ingest 生成，snapshot 固化，restore 执行。 执行前必须重新校验白名单，不能执行任意历史命令或用户 prompt。
binding_confidence high / medium / low。 snapshot capture 绑定 terminal 时生成。 marker 命中为 high；cwd/process 兜底为 low；低置信绑定不自动执行。

实现架构

实现采用四层拆分：wrapper 负责启动真实 CLI 并注入本次 terminal_key；agent 原生 hook 把 session 元数据写回当前 terminal 状态；snapshot collector 通过 osascript 调用 Ghostty AppleScript 采集工作区布局并把 terminal/pane 与状态记录绑定；Ghostty adapter 按快照重建 window / tab / terminal split，并在对应 terminal 输入白名单 resume 命令。

Operator
  │
  ├─ zagent install codex        →  生成 Codex native hook / ingest 入口
  ├─ zagent install claude       →  生成 Claude native hook / ingest 入口
  │
  └─ zagent codex|claude
        │
        ├─ 生成 terminal_key / run_id
        ├─ 写入 terminal name/title marker：__zagent_terminal___
        ├─ 注入 Z_AGENT_TERMINAL_KEY / Z_AGENT_RUN_ID / Z_AGENT_CWD / Z_AGENT_STATE_DIR
        ├─ 启动真实 codex / claude binary
        ├─ agent 原生 hook → zagent hook ingest
        └─ 更新 ~/.local/share/z-agent/workspace_state.json.active_terminals[terminal_key]

zagent snapshot capture
  │
  ├─ 调用 osascript / Ghostty AppleScript
  ├─ 读取 Ghostty windows / tabs / terminals
  ├─ 从 terminal name/title / cwd / process 识别 terminal_key
  ├─ 按 terminal_key 绑定 active terminal
  └─ 覆盖写入 ~/.local/share/z-agent/workspace_state.json.latest_workspace

zagent restore
  │
  ├─ 读取 workspace_state.json.latest_workspace
  ├─ 生成内部恢复计划
  ├─ 校验每个 terminal 的 restore_cmd 是否为白名单命令
  └─ 调用 osascript / Ghostty AppleScript → 重建 Ghostty 布局 → 在对应 terminal 输入 resume 命令

命令契约

下面是本方案要求代码对齐的目标命令契约。安装仍然按 agent 分端执行；恢复入口固定读取 workspace_state.json.latest_workspace。

# 能力诊断：不写入、不安装
python3 src/z_agent/cli.py doctor

# 分端安装：写入 hook ingest 和原生 hook 配置示例
zagent install codex
zagent install claude

# 显式通过 zagent 启动真实 CLI，并把 terminal_key 注入当前 terminal/pane
python3 src/z_agent/cli.py codex
python3 src/z_agent/cli.py claude

# agent 原生 hook 调用入口：从 stdin 接收 hook JSON，只提取元数据
zagent hook ingest --agent codex --json < hook-event.json

# 采集当前 Ghostty 工作区快照：内部通过 osascript 访问 Ghostty AppleScript
zagent snapshot capture --name working-now
zagent state show --json

# 恢复 Ghostty 布局
zagent restore

active_terminals 用于保存当前 terminal 与 Agent session 的绑定关系。latest_workspace 是恢复布局和启动 resume 命令的唯一入口。previous_workspace 保留一份上次快照，供手动回退。

布局数据以 Ghostty AppleScript 暴露的对象和属性为稳定契约。本期快照记录 split 方向、pane 顺序、cwd、title、process、terminal_key 和 session 绑定；不承诺保存 pane 的像素尺寸或 60/40 这类精确分屏比例。

Review 后执行路径

  1. 先跑 python3 src/z_agent/cli.py doctor，确认 Codex binary、Claude Code binary 和原生 session 目录探测是否符合预期。
  2. 执行 zagent install codex 或 zagent install claude 写入 hook ingest 和原生 hook 配置示例。
  3. 检查生成的 config/hooks/*-native-hooks.json 和 *-hook-ingest.sh；确认后再把 hook 配置合并到对应 agent 的原生 hook 配置里。
  4. 用 zagent codex 或 zagent claude 启动 Codex / Claude Code，并在 Ghostty 的多个 tab / split 中建立几组真实 Agent session。
  5. 执行 zagent snapshot capture --name review-case，授权 macOS Automation 访问 Ghostty，并生成当前 Ghostty 工作区快照。
  6. 执行 zagent state show --json 检查快照是否包含预期 window、tab、terminal、cwd 和 resume 命令。
  7. 执行 zagent restore，确认 Ghostty 能重建布局并恢复智能体会话。

扩展性

Agent spec 新增 AI CLI 新工具可按独立 agent spec 加入 binary、session roots 和 resume template，不影响 Codex / Claude Code。
Native hook 生命周期接入 agent 原生 hook 通过 zagent hook ingest 更新当前 terminal 元数据；snapshot collector 按 terminal_key 把它绑定到具体 Ghostty terminal。
Planner 未来多 Agent 编排 可在 workspace state 上增加计划层：根据技术文档创建 window/tab/split terminal、启动子 Agent、分派任务、回收状态。
Ghostty layout 布局表达能力 本期保留 Ghostty 布局树字段；后续可扩展为按项目、agent 类型、任务阶段生成可复用布局模板。

风险与验证

风险 控制方式 当前状态
Ghostty 布局采集不完整 用真实 window / tab / split 组合生成快照，检查 split_tree、pane 顺序、cwd 和 tab 归属是否稳定。 需真实 Ghostty 回归
分屏比例无法精确还原 快照契约以 split 方向和 pane 顺序为主；pane 像素尺寸和比例字段只有在 AppleScript dictionary 暴露稳定属性时才纳入 schema。 边界明确
pane 与 session 绑定错误 wrapper 注入 terminal_key 和 terminal name/title marker；hook 更新 active_terminals；snapshot capture 绑定时保留绑定依据和置信度。 需代码对齐后验证
terminal title marker 读取失败 优先从 terminal name/title 读取 __zagent_terminal_...__；失败时可用 cwd、process、启动时间窗做低置信度兜底，恢复时拒绝自动执行低置信绑定。 需真实 Ghostty 回归
快照过期 latest_workspace 记录 captured_at、window/tab/terminal 数量和 session 状态；恢复前使用最近一次快照。 需在 restore 输出中呈现
误执行命令 只允许脚本生成的 codex resume / claude --resume；restore 执行前做白名单校验。 命令白名单保留
Ghostty AppleScript 版本差异 基于官方 AppleScript API；真实执行前先验证 layout capture 和恢复白名单。 需目标机授权和版本验证
macOS Automation 权限缺失 首次调用 osascript 控制 Ghostty 时依赖系统授权；doctor 或 snapshot capture 应输出可读错误和恢复指引。 需真实授权流程验证
pane 中没有 Agent session latest_workspace 保留该 pane 的 cwd 和 shell 信息；restore 时只恢复 shell pane，不生成 agent resume 命令。 按设计处理
